# iPhone 主屏幕 Web App 部署与验收

## 发布

PWA 继续使用同域名 React 前端和 FastAPI。外部地址需为有效 HTTPS；Cloudflare Tunnel 在外部提供 HTTPS、在本机连接 HTTP Nginx 的部署方式可继续使用。

构建并使用原部署流程更新：

```bash
npm --prefix web-react ci
npm run web:build
./package-pi.sh
```

服务器按 [部署说明](README.md) 解压和更新。`pi-start.sh` 调用 `pi-nginx.sh`，它会检查配置、先复制资源，再分别原子替换 `index.html` 和 `sw.js`，并保留旧哈希资源供已打开的页面使用。本轮只提供代码及本地验收，不代表已经发布到服务器。

部署后打开 `https://你的域名/install`，页面在设备本地生成当前域名的安装二维码，可保存图片。登录页及“更多”也提供安装入口。不要把本地验证截图中的 `127.0.0.1` 二维码发给用户。

## iPhone 安装

1. 使用 iPhone 相机扫码，在 Safari 打开安装页。
2. 打开分享菜单，选择“添加到主屏幕”；部分系统版本需要先打开页面菜单。
3. 若有“作为 Web App 打开”开关，保持开启，确认添加。
4. 点桌面图标，登录。需要长期保留登录时使用现有“记住登录”选项。

二维码只能打开引导页，添加仍需要用户确认。Safari 与主屏幕 Web App 的登录状态可能不同，分别验收。

## 缓存与版本更新

- `/sw.js`、`/index.html`、Manifest 使用 `no-cache`，带哈希的 `/assets/` 资源使用长期缓存。若有 CDN，应遵循这些响应头，不对 HTML 和 Worker 设置长期边缘缓存。
- Worker 只预缓存公开的应用外壳、JS、CSS、图标和 Manifest。API、流式请求、私人文件与上传响应不进入 Worker 缓存。
- 已缓存的应用可离线显示界面和提示；聊天、事项、资料写入仍需联网。网页重新加载不会保留未发送附件，不提供离线写入队列。
- 发现新版本时提示更新，不自动刷新。先完成生成、上传，处理各会话草稿，关闭编辑弹层，再点“更新”。
- 还有本站其他窗口时，更新会要求先关闭它们。这也覆盖可能被系统暂停、无法确认是否存在未保存操作的窗口。
- 首次安装不显示更新提示。开发服务器默认不注册 Worker；在生产构建和 HTTPS 测试站点上验收。

## 照片与文件

聊天附件面板提供拍照、选照片、选文件。按单文件顺序上传，每条消息最多 10 个附件，每个文件最多 25 MiB；Nginx 请求体上限为 26 MiB，为单文件和 multipart 留出空间。旧客户端的批量上传也受单次请求体上限约束。

压缩默认关闭，启用后仅处理聊天图片副本；保存到资料时也会保存该副本。文档不压缩。HEIC 尝试通过浏览器解码转换为 JPEG；不支持时明确提示导出 JPEG，不承诺所有 iPhone HEIC 场景已经通过。相机与图库选择界面由系统决定。

失败附件可单独重试；取消会中止客户端上传，但服务器已经接收的文件不保证自动删除。发送结果不明时先核对会话，不自动重新发送同一条消息。

## 发布检查

```bash
curl -I https://你的域名/sw.js
curl -I https://你的域名/manifest.webmanifest
curl -I https://你的域名/index.html
curl -I https://你的域名/assets/不存在.js
```

前 3 项应及时重新验证，缺失资源应为 404，不能返回 SPA 的 HTML。真实 `/assets/` 哈希资源应含 `immutable`。`/api/`、`/files/` 和 `/generated/` 优先反向代理，含 `.png` 等后缀也必须走权限检查。

验证首次安装设备与已有安装设备；确认更新不会打断输入和生成。服务器及 Tunnel 必须持续运行，PWA 不在手机本地执行 Agent。

## 自动验收

```bash
npm run web:typecheck
npm run web:lint
npm run web:test
npm run web:build
python3 scripts/validate_pwa.py
python3 scripts/validate_home_workbench.py
```

浏览器脚本使用隔离账号、临时数据和模型桩，不调用外部模型。PWA 脚本优先启动独立 Nginx 配置，不使用或重载系统站点；没有 Nginx 时回退到 Vite preview。它临时修改构建目录里的 Worker 来模拟版本发布，结束时恢复；应在独立本地构建目录运行，不能直接对正在提供线上静态服务的 `dist` 执行。

PWA 结果及截图在 `.data/validation/pwa/`；工作台回归在 `.data/validation/home-workbench/`。浏览器验收不能替代 iPhone 的真实键盘、相机、照片格式、独立窗口和系统手势验收。

## iPhone 真机记录

每次填写设备型号、iOS 版本、HTTPS 域名和构建版本。以下项目未在本地 Chrome 验收中冒充完成：

- 扫码、实际添加、图标和重新打开。
- 中文候选栏、表情、听写、连续开关键盘 10 次、多行输入和横竖屏。
- 生成时上滑读历史、图片加载、返回会话与弹层关闭后的阅读位置。
- 真正拍照、相册多选、方向、大图、HEIC 转换及弱网取消重试。
- 下拉面板、回弹、反向拖动、系统边缘返回和文本选择。
- 锁屏、切后台、重新打开后核对结果；当前后端仍可能因连接取消而中断生成。
- 200% 文字、VoiceOver、减少动态效果及深色模式。
- 已有安装升级、两个窗口、离线启动、恢复联网和回滚。

## 回滚与停用

回滚应恢复兼容的 HTML、资源和 Worker，并继续保留已发布的哈希资源。回滚包建议重新构建，让构建资源清单与目标代码一致。Worker 内容不同即可触发浏览器更新，不能只替换 HTML 或删除服务器上的 `sw.js`。

需要完全停用时，将 `deploy/pwa-disable-sw.js` 发布到原 `/sw.js` 路径，继续使用 `no-cache`。已打开的页面检测更新后，需要关闭本站所有窗口，让恢复 Worker 激活；下一次打开将走网络页面。恢复 Worker 只清理 `claw-home-` 开头的 Cache Storage 并注销自身，不删除账户、服务器数据或其他应用缓存。停用期间保留该文件，给已有设备留出获取更新的时间；这不是常规升级流程。
