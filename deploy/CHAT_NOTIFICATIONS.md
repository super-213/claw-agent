# 后台生成与回复完成通知

## 使用方式

用户从 iPhone 主屏幕打开 Web App，进入“更多 → 账号与设置 → 回复通知”，点击“开启回复通知”并允许系统通知。iPhone 需要 iOS 16.4 及以上；普通 Safari 标签页不作为 iPhone 推送验收入口。平台要求见 [Apple 官方说明](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)。

新前端会先创建服务器任务，再查看流式结果。切后台、锁屏、关闭页面或网络断开只会断开查看连接，任务继续在服务器运行。重新打开同一对话后，页面查询当前任务状态并读取已保存的回复。需要真正终止时使用“停止生成”。

通知默认只显示“回复已完成，点击返回对话查看”，不包含问题、回答、资料名或工具参数。点击通知打开对应对话，仍需通过登录和权限检查。正在阅读该对话时，前端确认已读；服务器预留 5 秒再发送通知，减少重复提醒。单纯停留在首页不会把后台回复误标为已读。

## 服务器配置

保留现有 HTTPS 域名、Nginx 和 FastAPI 部署。按原流程安装 `requirements.txt`；其中已有 `pywebpush>=2.0.0`。在服务器 `.env` 或 `config/.env` 中填写真实联系地址：

```dotenv
WEB_PUSH_SUBJECT=mailto:替换为你的真实运维邮箱
HOME_REMINDER_DELIVERY_ENABLED=false
```

`WEB_PUSH_SUBJECT` 也可为有效的公开 HTTPS 联系页面，不能使用 localhost。联系地址缺失或依赖不可用时，设置页会提示服务器尚未配置，后台生成仍可使用。

公私钥同时留空时，首次读取设置会自动生成 `HOME_DATA_DIR/chat-vapid-private.pem`，文件权限为 0600，后续持续复用。原子写入避免进程意外中止留下半个密钥文件。也可以通过 `WEB_PUSH_VAPID_PUBLIC_KEY` 和 `WEB_PUSH_VAPID_PRIVATE_KEY` 同时提供已有密钥；私钥格式沿用 pywebpush 支持的文件路径或编码格式。

服务器需能向浏览器返回的 HTTPS 推送服务端点发起请求，例如 Apple 的 `*.push.apple.com`。无需 Apple 开发者账号或 APNs 原生证书。当前订阅接口接受 Apple、Google FCM、Mozilla 和 Windows 的已知推送服务域名，拒绝任意自定义 URL。

用户必须主动允许通知；后台不会自动弹出权限请求，也不会自动为新登录账号启用旧账号的订阅。

## 任务与状态恢复

- 任务、事件、设备绑定和通知发件箱保存在 `HOME_DATA_DIR/chat_jobs.sqlite3`。同一账号与请求标识重复提交返回同一个任务，内容不同时返回冲突。
- 同一会话最多一个正在执行的后台任务；每个账号最多 4 个并发任务，服务合计最多 16 个。执行期间，旧接口的新聊天、删除会话和分支修改会拒绝冲突操作。
- 回复写入会话后才把完成通知加入发件箱。通知失败不会丢失或撤销模型回复。
- 服务器重启时将运行中或排队中的任务标为中断，保留原请求和检查点；不会自动重新执行。存在运行检查点时，用户可选择“从检查点继续”。
- 工具需要授权时保留“查看并确认”。恢复时若某项非幂等操作结果不明，暂停并显示“核对操作结果”；用户可明确选择按成功或失败继续、授权重新执行或结束任务。不会仅因为断线自动重复写入。
- 尚未开始、没有运行检查点的中断任务无法自动续接；核对已保存的对话后重新提问。原请求元数据保留在任务库中。
- 新的授权或恢复任务会将旧的等待记录标为已继续，避免旧记录永久阻塞会话。待确认或待核对操作处理前，不接受该会话的新问题。

当前使用本机持久化和单个后台执行进程。Uvicorn 必须使用一个 worker；第二个执行进程会因任务锁无法获取而拒绝启动。要扩展多 worker 或多服务器，应另行迁移为共享任务队列，不能直接增加 `--workers`。

## 推送重试与退出登录

每个任务与设备最多保留一条通知记录。失败最多尝试 5 次，使用逐步增加的重试间隔；404 或 410 会停用失效订阅。通知有效期为完成后一小时，过期后不再发送。

发件箱在服务器重启后继续处理。推送服务已经接收、但本机还没记录成功时发生崩溃，可能再次发送；相同任务使用稳定 `tag`，尽量在系统中合并。网络推送无法提供绝对的恰好一次到达保证。

订阅绑定当前账号和登录会话的指纹，不保存原始登录 Cookie。发送前重新检查账号有效、登录未过期、订阅仍启用、任务未被阅读。

退出登录会先在服务器撤销该登录会话的设备绑定和待发通知，再尽力取消浏览器订阅并关闭已显示的回复通知。其他仍登录的设备可以继续接收。已经被推送服务接收的通知可能仍在途中，无法从服务器撤回；通知内容因此保持通用，不展示私人正文。

## 数据备份与回滚

在停服状态下备份整个 `HOME_DATA_DIR`、会话目录和运行记录，包含 `chat_jobs.sqlite3` 与 VAPID 私钥。在线备份 SQLite 时应使用 SQLite backup API，不能在事务写入中只复制数据库文件。

保留原私钥；丢失或更换会使现有浏览器订阅需要重新开启。发布包不包含运行数据库、私钥或账号凭据。

事件日志启动时清理超过 7 天的已结束任务事件，任务元数据和去重记录保留 30 天。单个模型阶段结束后保留最近约 20000 条事件；任务完成后的权威回复仍在会话存储中。长时间运行且不重启的实例需要配合运维定期重启或后续增加独立维护任务。

回滚到旧后端前先等待任务完成或明确停止任务，然后备份。旧版本不会处理新发件箱；可以先让用户关闭回复通知，再回退代码。家庭事项提醒开关保持原值，不用于启停回复通知。

通知浏览器脚本使用延迟模型桩和测试推送捕获，验证关闭全部页面后继续执行、回复持久化、发件箱去重、重新打开对话、退出登录撤销绑定，并通过 Chrome 开发工具注入推送验证 Service Worker 展示通知。不会向真实设备发送外部推送。
