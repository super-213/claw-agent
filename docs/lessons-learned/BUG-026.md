# BUG-026 对话加载期间输入框整体禁用

- 发现日期：2026-10-30
- 状态：代码已修复，19 项聊天回归及生产构建通过；前端构建已输出到部署目录

## 现象与影响
进入对话页需要等待一段时间才能输入文字，网络较慢时影响连续使用。

## 复现条件
延迟会话列表或详情请求；技能或配置读取慢也会推迟首次打开会话。

## 排查证据
- `ChatWorkspace` boot 原先先 await 技能与配置，再读取会话列表和详情。
- `Composer` 的 disabled 同时控制输入、发送和附件；会话未 ready 时整体禁用。
- 首次会话 ID 从 null 切换到目标 ID 时，Composer key 改变会重建输入控件；草稿键也从 new 切换到会话 ID。
- 新增延迟请求组件集成测试重现该流程，验证输入与焦点在完成加载后保留。

## 原因
本地文字编辑被绑定到服务器会话准备；可并行的非关键读取阻塞启动流程；直接解除禁用还会遇到首次选择会话时丢失当前输入/焦点的问题。

## 修复内容
- 为 Composer 区分 inputDisabled 与操作 disabled，默认行为兼容现有调用。对话加载时允许文字、技能及成员输入，发送和附件仍等待会话 ready；任务繁忙时保持现有输入限制。
- 技能与配置请求并行在后台执行，不再阻塞会话加载。
- 首次选择会话保持输入组件实例；初始 new 草稿转入目标会话，已有草稿存在时合并保留。
- 真正切换不同会话仍重建附件组件，保留会话隔离与上传清理。
