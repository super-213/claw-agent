# BUG-027 macOS 重启时旧 LaunchAgent 注册导致后端未启动

- 发现日期：2026-10-30
- 状态：代码已修复；回归及实际重启验证通过，运行服务已恢复

## 现象与影响
`bash deploy/mac.sh restart` 报启动检查失败。网页 HTTP 200，API HTTP 502，后端 LaunchAgent 未运行，Nginx 上游连接被拒绝。

## 复现条件
重启过程中 `bootout` 返回后旧服务仍可被 `launchctl print` 查询，而启动逻辑仅在查询不到服务时 bootstrap。旧服务随后退出，后端没有重新注册。

## 排查证据
- 实际 status：网站 200、API 502，后端无运行状态；日志出现上游连接拒绝。
- 再次执行 start 后服务立即恢复并返回健康检查 200。
- 原脚本 stop 后立即 start，没有等待注销；启动逻辑跳过仍可查询到的服务。
- Shell 模拟延迟注销复现该时序，验证等待逻辑及超时停止。
- 实际故障时未记录 launchctl 每一瞬间状态，因此时序与源码、恢复行为一致，但不能将日志当作该瞬间完整跟踪。

## 原因
已确认脚本存在停止与启动的时序缺口：注册存在不等于服务仍会保持运行。原健康检查只发现启动失败，没有补回被跳过的后端。

## 修复内容
每个服务 bootout 后，最多等待 10 秒，确认 launchctl 不再返回旧注册，才允许后续启动；超时明确报错并停止，不继续误判启动成功。保持原有权限和配置范围。

## 验证结果
- `bash -n deploy/mac.sh` 通过。
- 新增 2 项 Shell 回归：等待延迟注销、超时不继续启动，均通过。
- 实际先执行 start 恢复服务；修复后执行 restart 成功，网站及 API 均通过脚本健康检查。
- 部署全量测试 7 项通过，包含真实临时 Nginx 代理验证。
- 同次重启加载便笺后端文件存在性校验；未对生产便笺写入测试数据，未做手机真机验证。
- 日志中的 activity_lifecycle UnicodeDecodeError 是另一个未定位问题；不能据此断定本次启动失败根因。
