# BUG-008：过期未完成事项无法补标完成

- 发现日期：2026-10-30
- 状态：代码已修复并通过相关回归；运行服务尚未重启，前端尚未重新构建部署。

## 现象与影响

用户在首页“需要关注”区域点击逾期事项的“完成”，出现“该事项已过期，无法修改”。用户已处理但忘记勾选的事项无法补记，会继续作为未完成事项显示。

## 复现条件

活动状态的有日期事项已有未完成期次，服务端所在时区已进入截止日次日。由该期负责人通过首页完成接口或聊天卡片提交完成操作。

## 排查证据与已确认原因

- 用户截图显示逾期事项仍有“完成”按钮，但点击后返回过期错误。
- 首页 `HomePage.tsx` 的 `run` 使用原期次 ID 调用 `tasksApi.change(..., 'complete', ...)`。
- `task_card_policy.readonly_reason` 优先返回 `expired`；原 `assert_writable` 对所有操作统一抛出 `task_card_expired`，包括 `complete`。
- `TaskCardsMixin._card_view` 对过期事项不提供任何操作，聊天卡片也无法补记。
- 既有 `test_expiry_server_clock_freezes_old_and_new_write_routes` 明确要求过期完成接口返回 409。这是已确认的策略限制，不能归因于前端网络失败或模型未选工具。

## 修复内容

- 在统一写入策略中，只允许活动、可执行且期次仍为 `open` 的过期事项执行 `complete`。负责人身份、乐观版本、请求幂等和多人 all/any 规则仍由原服务检查。
- 聊天卡片只向尚未完成本人份额的负责人提供 `complete`，不开放内容编辑或其他操作；提示说明可以补标完成。
- 已完成、取消、跳过、归档和暂停的历史事项继续受限；周期事项使用原期次，不转到当前期。
- 完成时间记录实际补勾提交时间，不推断用户实际处理时间。
- 更新原先“跨日即所有操作只读”的测试预期，增加权限、混合修改原子回滚、原期次及持久化验证。

## 后续预防
