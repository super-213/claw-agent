# BUG-016：更多目录限宽且单列导致宽屏右侧大片留白

- 发现日期：2026-10-30
- 状态：代码已修复；构建、首页回归和浏览器布局验证通过，未部署。

## 现象与影响

“更多”目录在横屏和桌面宽屏下，菜单只占左侧，右侧大片空白；多个分组纵向堆叠，增加滚动距离。

## 复现条件

进入 `/home/more`，以桌面宽屏或手机横屏查看；管理员可见个人设置、便捷使用和管理员工具三个分组。

## 排查证据与原因

- 用户截图显示目录左对齐且右侧没有内容。
- 已确认 `.home-more { max-width: 840px; }` 同时约束目录与二级内容，目录分组也没有横向网格。
- 这是前端布局限制，不涉及接口数据缺失或管理员权限错误。

## 修复内容

- 目录增加独立类，解除目录的 840px 限宽，保留二级页阅读宽度。
- 分组容器采用自适应网格，按可用空间排为一到三列；普通用户两个分组自动铺开。
- 保留现有列表分隔线、焦点反馈与权限控制，长文本允许换行。

## 验证结果

- `npm --prefix web-react run build`：通过，包含 TypeScript 检查和 PWA 构建；仍有现有 JS chunk 超过 500kB 的提示。
- `npm --prefix web-react run test -- test/web-react/home/home-page.test.ts`：10 项通过。
- Chrome/Playwright 使用独立 Vite 端口和拦截的示例 API：管理员、普通用户 × 深浅色 × 320/390/844/1024/1440/1920px 共 24 组布局检查通过，无页面异常、无横向溢出。
- 管理员上述宽度分别为 1/1/2/2/3/3 列，普通用户为 1/1/2/2/2/2 列。目录占满内容宽度；账号、操作记录及管理员成员页面共 60 次返回检查通过，二级内容宽度不超过 840px。
- 人工查看 1440px 深色和 390px 浅色截图，分组及单列显示正常。
- 首次沙箱中 Chrome 启动失败，扩大执行权限后完成浏览器验证；不是产品失败。
- 未调用真实模型、外部业务 API 或真实账号；未验证真实业务写入，未执行全量后端测试。代码与构建产物已更新，未部署、未重启用户运行服务。

## 后续预防

目录页和阅读页分别定义宽度；按容器可用宽度适配，避免仅按屏幕方向判断。布局验证覆盖普通用户与管理员、窄屏和宽屏，不仅断言菜单存在。
