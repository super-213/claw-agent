# BUG-006：业务钩子迁移的授权、回执与资源事件时序回归

- 发现日期：2026-10-29
- 状态：迁移开发中发现、修复并通过完整后端回归；运行服务尚未重启。

## 现象与影响

P3 将任务、留言板和知识库逻辑改为扩展钩子后，普通聊天/附件请求在模型请求前失败，两个会话的并发模型调用计数为 0；另一个用例已经成功创建事项，但模型最终返回空文本后，运行未生成保存回执而失败。

完整复跑还发现，30 条批量事项的结果转存为产物后，没有发出 `task_changed` 刷新事件。

这是本轮开发回归，不表示已部署服务发生过相同故障。

## 复现条件

- 在启用业务插件的 Web 环境执行普通聊天或上传附件聊天，测试使用 FastAPI 测试身份。
- 创建工具成功后，模型返回不含工具调用的空回答。

## 排查证据

- `test/test_chat_async_concurrency.py::test_stream_chat_runs_different_sessions_concurrently`：迁移中实际观察到 `max_active == 0`。
- `test/test_media_api.py::test_uploaded_image_and_document_reach_model_and_survive_reload`：非流式返回 403，流式没有完成事件。
- `test/test_task_chat_creation.py::test_successful_creation_still_has_a_receipt_when_model_final_is_empty`：实际保存后 `run_status` 为 `failed`。
- 钩子中的 `system_messages`、`defer_output`、回答校验统一调用了带会话访问检查的工具执行上下文；新的回答处理块又加上了 `content.strip()` 条件。

## 已确认原因

1. 业务提示和输出缓冲判断只需要本轮的宿主选择元数据，却提前触发了专供真实工具执行使用的完整授权上下文。测试身份与真实用户存储不同，导致在模型请求准备阶段提前拒绝，而不是工具执行阶段才做相应检查。
2. 原有事项守卫可以从本轮成功工具证据补齐空回答回执；迁移把守卫放在“内容非空”的分支下，遗漏这一合法流程。

3. 将资源事件生成迁入钩子时，错误地放到了大工具输出 externalize 之后。原结果已经换成产物引用，钩子无法读取 `task_changed`；最终复跑实际出现 575 项通过、该批量用例失败。

## 修复内容

- 动态提示、缓冲判断和回执守卫使用运行中由宿主准备并持久化的选择上下文；工具 handler、来源校验和资源访问仍调用完整授权上下文。
- 对所有不含工具调用的回答运行校验，包括空文本；只有需要处理文本的来源补全步骤保留非空条件。
- 在结果 externalize 之前生成通用扩展事件，之后沿原顺序发送，避免截断或转存丢失业务刷新信号。
- 没有增加 TESTING 授权豁免，也没有放松真实账号、会话或上传文件的权限检查。

## 验证结果

- 修复后，聊天并发、媒体 SDK 请求/持久化、任务创建回执相关 51 项通过。
- 增加插件边界测试后，同组扩展回归 61 项通过。
- 最终后端回归 576 项通过、1 项真实 Nginx 用例因沙箱限制排除；前端 99 项通过。后端使用临时依赖目录和禁止外网连接的测试保护，命令与范围记录在 `docs/015-tool-plugin-architecture-plan.md`。
- 迁移初次广回归另有 PDF、推送依赖缺失，不能把环境缺依赖写为本问题的代码根因。
- 没有调用真实模型或操作真实设备；未重启服务或部署。

## 后续预防

业务钩子迁移分别验证模型请求准备、执行授权、工具结果、最终回答和持久化。必须覆盖无业务工具的普通聊天、上传输入、并发请求和工具成功但模型最终文本为空的情况。
