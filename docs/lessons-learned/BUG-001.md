# BUG-001：图片识别会话错误调用文本工具，联网请求被 Fake-IP 检查拦截

- 发现日期：2026-10-29（Asia/Shanghai）
- 状态：代码已修复并验证；运行服务尚未重启
- 影响范围：带图聊天的模型路由、工具选择、文件路径处理、公网 HTTP 访问和请求日志

## 现象与影响

当天 10:02，用户在“这个是什么番的角色”会话中附上图片。助手先调用 `file_read` 读取图片路径，失败后声称无法读取图片；随后请求维基百科失败，又将单次请求失败概括为无法访问外部网站。

用户配置的主模型为 `qwen3.8-27b`，视觉模型配置留空。用户预期该主模型直接处理图片并在必要时联网核实。

## 复现条件与排查证据

1. 原会话保存了用户消息及图片元数据，上传文件仍存在。模型调用 `file_read`，参数为 `/generated/uploads/…jpg`，工具返回 `path_outside_allowed_roots`。
2. 模型确实调用了 `http_request` 请求维基百科，工具返回 `private_network_requests_are_not_allowed`。请求在本地地址检查阶段被拒绝，没有取得网页响应。
3. 本机当时将 `zh.wikipedia.org` 解析为 `198.18.0.214`；其他公网域名也解析到 `198.18.*`。该表现符合代理 Fake-IP DNS 的特征，但未通过代理配置文件确认具体配置。
4. 旧模型路由根据模型名是否包含 `vl` 决定是否切换视觉模型。当前配置和同一图片在修复前的代码中构造出的 SDK 请求，实际选择 `qwen3-vl-plus`。
5. 旧运行事件只记录默认主模型名，没有记录最终 SDK 请求选定的模型、成功附带的图片数量及转换错误，因此无法从历史日志还原当次实际发出的视觉请求。

复现图片路径拒绝和域名检查错误时均得到了与原会话相同的错误。

## 原因

### 已确认的实现缺陷

- **模型配置语义不一致**：视觉模型留空时，程序依赖名称中是否有 `vl` 的启发式判断，擅自替换用户选定的主模型。模型名称不能作为视觉能力的可靠判据。
- **文件工具与上传接口约定不一致**：`/generated/…` 是 Web 路径，`file_read` 却将其作为磁盘绝对路径检查。该工具按 UTF-8 读取文本，本身也不适合读取 JPG。
- **地址检查未适配 Fake-IP 环境**：安全检查把合成 DNS 地址视为非公网地址，导致公网域名在请求发出前被拒绝。
- **可观测性不足**：日志使用配置中的默认模型名，无法证明实际选用了哪个模型、图片是否转换成功。

### 从会话行为确认的问题

- 模型选择了不适合图片的文本读取工具。
- 模型把某个工具或某个来源的失败扩大为自身能力限制，提前停止任务。

### 未确认及不能推导的结论

- 不能仅凭“我无法读取图片”认定图片没有到达模型；历史请求证据不足。
- 不能因一次 HTTP 请求失败就认定模型没有联网工具，或认定维基百科主动拒绝了该请求。
- 该轮提供了 35 个工具，包含与识图无关的业务工具；这可能增加选择负担，但本次未通过对照实验确认它是失败原因。

## 修复内容

1. 视觉模型留空时使用主模型；只有管理员明确配置了独立视觉模型时才切换。设置界面同步说明这一行为。
2. 保留真实 `image_url` 输入，并注入运行时说明，引导模型直接观察图片，不用 `file_read` 读取图片或仅凭文件名判断。
3. `file_read` 将 `/generated/` 与 `/files/` 映射到生成目录，对别名路径继续进行目录边界与权限校验；图片返回明确的视觉输入提示，避免出现误导性的文本解码错误。
4. 对域名解析结果全部属于 `198.18.0.0/15` 的情况，通过固定地址、TLS 验证的公共 HTTPS DNS 查询真实公网 IPv4；验证返回地址后固定连接该地址，保留原域名的 Host、TLS SNI 和证书校验。
5. 字面 Fake-IP、私网地址、含非公网地址的混合解析结果和重定向仍拒绝；DNS 回退失败时明确报错，不关闭内网保护。
6. 模型请求完成/失败事件和模型步骤记录实际请求模型、图片数量及媒体转换错误；请求开始事件区分配置模型。诊断数据不记录图片 Base64。

## 验证结果

### 自动化检查

- 相关后端测试 75 项通过；随后利用临时指定的已安装依赖路径单独验证 PPTX 测试，1 项通过，合计 76 项通过。
- 设置界面测试 6 项通过。
- 前端生产构建成功，`git diff --check` 通过。
- 扫描 PDF 测试未完成：本机默认 Python 缺少 `pymupdf`。没有将该项计为通过。
- 新增检查覆盖：私网和字面 Fake-IP 拒绝、混合地址拒绝、公共 DNS 私网答案拒绝、解析失败关闭访问、固定目标地址、中文 URL 编码、上传路径越界防护、默认多模态模型保留、媒体失败诊断及请求日志持久化。

### 真实环境检查

- 使用修复后的 `http_request` 请求原维基百科地址，返回 HTTP 200。
- 使用已配置的 `qwen3.8-27b` 和原图片发起真实请求，诊断显示 `image_count=1`、`media_errors=[]`，模型能描述可见特征。
- 隐藏原文件名的首次检查中，模型将角色误认成其他作品角色。这说明输入送达不等于识别准确。
- 保留原消息并提供文本读取工具的后续原生工具协议检查中，模型没有调用 `file_read`，直接回答《坂本日常》的篁。但原文件名仍包含线索，该结果不能作为无文件名提示的纯视觉识别准确率证明，也未核实模型补充的角色或制作信息。

上述检查验证了特定请求与环境，不保证模型以后每次都正确识别或选择工具。

### 生效情况

代码及前端构建产物已更新；此次未重启现有后端服务。运行服务需加载新代码后才会使用修复逻辑。原会话历史未改写。

## 后续预防与尚未实施项

- 模型、附件、工具协议及网络环境的改动，验证最终请求和执行结果，不能以“已注册工具”或“已生成图片编码”代替任务完成验证。
- 日志不足时保留不确定性，避免将模型自述当作根因。
- 按任务筛选相关工具、完善失败恢复和目标完成检查是后续方向；本次没有实现通用工具筛选或通用完成度判定机制。
- 重启后验证实际服务的新请求日志，补跑扫描 PDF 测试。
