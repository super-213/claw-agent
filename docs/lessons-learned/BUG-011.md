# BUG-011：服务器不可达时对话页仍显示就绪，离线浮条遮挡输入区

- 发现日期：2026-10-30
- 状态：代码已修复，定向回归、构建与桌面/手机浏览器验证通过；尚未部署。

## 现象与影响

用户截图显示：服务器不可达、页面使用缓存时，底部离线浮条盖在输入区上方，右上角仍显示“就绪”。连接信息与任务状态相互矛盾。

## 复现条件

打开已缓存的对话，在浏览器断网或 API 网络失败回退缓存后查看顶部状态及输入区。手机布局原本隐藏顶部状态。

## 排查证据

- `PwaStatus` 单独维护缓存回退标记，监听 `claw-cache-fallback`，渲染固定定位的 `pwa-offline`。
- `ChatWorkspace` 只读取任务的 `statusText/currentBusy`，没有读取浏览器在线状态或缓存回退标记。
- `chat-workspace.css` 在 860px 以下直接隐藏状态徽标。
- 已确认界面状态来源分离；没有排查或判定服务器不可达的具体网络原因。

## 原因

全局离线提示与聊天任务状态独立渲染，连接故障无法覆盖“就绪”，固定浮条又与输入区重叠。

## 修复内容

- 提取共享连接状态 Hook，供全局提示和对话顶部使用。浏览器离线显示“离线”，网络失败使用缓存时显示“连接中断”，附缓存说明 title。
- 对话状态优先显示连接故障；成功读取服务器数据（`claw-cache-fresh`）后恢复原任务状态。浏览器 online 事件本身不证明服务器恢复。
- 对话页（含工作台中的对话浮层）隐藏底部离线浮条；其他页面保留原提示。
- 手机布局保留顶部状态，故障圆点使用黄色，避免仅靠颜色传达状态；徽标使用 role=status。

## 验证结果

- `npm --prefix web-react run test -- test/web-react/chat/navigation.test.ts test/web-react/pwa/response-cache.test.ts`：2 文件、13 项通过。覆盖连接中断、离线、仅 online 不清除故障、fresh 后恢复，以及原有缓存隔离回归。
- TypeScript、生产构建（含 PWA）、修改文件定向 ESLint、`git diff --check` 通过；构建仍有主 JS 超过 500 kB 的提示。
- 本地生产预览 + Chrome：1440/390 宽度下徽标可见，浏览器断网显示离线，缓存回退事件显示连接中断，恢复后读取模拟接口回到就绪；浮条隐藏，无横向溢出及 pageerror。
- 浏览器 API 为模拟数据，缓存回退用事件模拟；没有宣称完成真实服务器故障或真实模型请求验证。未验证完整生产 service worker 断网刷新，本次未改缓存请求/存储协议。
- 首次浏览器启动因默认 Chromium 未安装、沙箱内 Chrome 启动失败而未执行检查，随后使用允许的本地 Chrome。模拟数据首次缺少树节点字段导致 pageerror，补齐 nodes 后通过；online 后自动身份请求会产生 fresh，浏览器预期据此修正为就绪。
- 代码和构建产物已更新；未部署运行服务。

## 后续预防

连接状态应与任务状态分开保存、统一展示优先级；检查离线提示时同时覆盖手机布局及聊天浮层，避免提示遮挡操作区。浏览器联网与服务器成功响应应区分。
