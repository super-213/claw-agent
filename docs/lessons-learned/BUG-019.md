# BUG-019：活动销毁需要覆盖离线缓存及聊天派生副本

- 发现日期：2026-10-30
- 状态：开发中发现，代码已修复并验证；运行服务未更新、未部署。

## 现象与影响

家庭活动开发时检查到：前端 `jsonRequest` 的离线缓存判定忽略 `cache: no-store`，并把 `/api/home/board` 纳入缓存；单独删除活动账本不能清理会话、Run 和后台聊天 SQLite 事件中的原生工具参数。开发初版若只清理账本，会残留派生副本。这是实施中发现的生命周期缺口，不表示正式环境已有家庭活动泄露。

## 复现条件

先读取含限时内容的留言板／活动，再离线；或通过原生工具创建活动后，销毁活动并检查相关持久化调用参数。另需覆盖旧备份恢复和后台事件重放。

## 排查证据

- 原 `cacheRead` 只检查方法和 `cacheableRead(url)`，未检查请求的 `no-store`。
- `ConversationStore`、`RunStore` 与 `ChatJobStore.events` 是独立持久化路径，账本删除不会触及它们。
- 新增测试实际验证：活动销毁前会话及后台事件包含合成派生字段，销毁／到期后不可读取，清理后磁盘参数被移除，延迟写入也不能恢复。

## 原因

已确认：HTTP 缓存策略与应用 IndexedDB 缓存是两层；真实资源和工具执行证据也是不同存储。仅检查领域对象不存在不能证明派生内容已销毁。旧备份的历史截止也不能覆盖活动当前已延长的期限。

## 修复内容

客户端遵守 `no-store`，活动／留言板／通知退出离线缓存；活动使用独立无正文销毁日志；备份只按已确认销毁标识净化，避免用旧期限误删仍有效活动。会话、Run 在读取／写入时执行授权期限净化，生命周期任务清理其磁盘副本；后台事件同样清理，SQLite 开启 secure_delete。原始用户输入由聊天管理，不承诺撤回外部已送达通知。

## 验证结果

`test/test_family_activities.py` 的备份恢复、延长期限、原生聊天持久化、后台事件与延迟写入检查通过；`test/web-react/pwa/response-cache.test.ts` 的 no-store／活动不缓存检查通过。完整结果见 016 实施记录。未部署。

## 后续预防及相关代码

每次增加可销毁资源，枚举账本、草稿、备份、Run、会话、事件与客户端缓存；对边界访问和后台清理分别验证。相关代码：`services/family_activity_store.py`、`family_activity_privacy.py`、`services/chat_jobs.py`、`agent_runtime/run_store.py`、`services/conversation_store.py`、`web-react/src/api/client.ts`。
