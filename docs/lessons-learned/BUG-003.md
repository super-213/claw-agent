# BUG-003：工具插件迁移中的注册、校验与发布兼容性

- 发现日期：2026-10-29
- 状态：开发回归中发现并修正；运行服务尚未重启。

## 现象与影响

时间工具迁移到插件后，原安全评估的未知参数错误从既有中文提示变成通用插件错误，破坏错误协议断言。Web 复用包含 CLI 插件的注册表时，重复注册时间工具导致构建失败。另外，发布脚本的源码目录白名单原本不含 `tool_plugins`，若直接发布新结构会遗漏已迁移工具。

这些问题在本轮开发与静态检查中发现，没有证据表明运行服务已经遇到这些故障。

## 复现条件与排查证据

- `test/agent_runtime/test_runtime_evals.py::test_runtime_safety_evaluation_set` 的 `unknown-argument` 案例期望“不是允许的参数”，首次迁移后返回 `plugin_arguments_invalid`。
- `test/test_family_task_api.py::test_loaded_file_tool_preserves_upload_ownership_for_web_aliases` 将兼容构建器结果提供给 Web；时间工具在复制及插件绑定时各注册一次，出现 `required_datetime_plugin_failed`。
- `deploy/build_pi_package.py` 原 `SOURCE_DIRS` 未包含 `tool_plugins`。此项是确定的文件清单缺失，未实际构建或部署错误发布包。

## 原因（已确认）

迁移不仅改变实现文件位置，也改变注册生命周期及校验入口。新完整 schema 校验提前替代旧错误表达；Web 未区分共享/CLI 插件定义与用户级重新绑定；发布白名单未同步源码布局。

## 修复内容

- 保留旧参数检查与错误语义，随后执行 Draft 2020-12 补充检查。
- Web 复制旧工具注册表时跳过带插件来源的定义，按当前用户重新装配插件；不通过放宽名称冲突检测修复。
- 插件在 CLI 基础工具注册后装配，避免可选插件抢占基础工具名。
- 发布源码目录加入 `tool_plugins`，仅额外打包示例 TOML，不包含操作者实际启用配置。

## 验证结果

- 插件测试 17 项通过：包括第二插件的 SDK 请求构造、原生工具结果回传、会话/Run 持久化、用户隔离、权限撤销、审批恢复、schema 限制、冲突与发布清单。
- 修复校验、重复注册及测试隔离后，相关后端回归最终 128 项通过，见实施计划第 11 节。
- 与 macOS 部署测试一起运行时，20 项通过，1 项失败：真实 Nginx 检查被沙箱禁止 `sysctlbyname(net.inet.tcp.sendspace)`。此日志只能证明环境权限限制，不能据此归因为应用缺陷；未为此修改部署配置。
- 未安排真实模型验收；整体回归出现意图模型未隔离问题，见 BUG-004。未构建正式发布包，未重启或部署运行服务。

## 后续预防

后续工具族迁移同时验证错误协议、Web/CLI 绑定来源、审批恢复和发布文件清单；不能仅验证 Python import 或单个 handler 返回成功。
