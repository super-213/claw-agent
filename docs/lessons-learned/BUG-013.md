# BUG-013：新建对话入口位于侧栏顶部，移动端触达不便

- 发现日期：2026-10-30
- 状态：代码已修复，构建及导航回归通过；浏览器验证通过；未部署。

## 现象与影响

用户反馈新建对话按钮位置太高。手机打开历史抽屉后，需要触达屏幕顶部才能开始新对话。

## 复现条件

打开 `/chat` 或 `/sessions/:sessionId`，手机宽度不超过 860px，展开历史抽屉。

## 排查证据

- 已确认：用户提供项目截图及手机 ChatGPT 底部聊天按钮作为参考。
- 已确认：`SessionSidebar.tsx` 将新建按钮放在历史列表之前；移动样式只调整抽屉，未改变操作顺序。
- 视觉检查发现：移动关闭按钮移到历史标题旁时，标题原有 `width: 100%` 和禁止收缩会将关闭按钮挤出；已明确设置标题弹性宽度。
- 单手触达改善属于布局设计判断，未进行真人可用性实验。

## 原因

新建操作沿用桌面顶部布局，没有针对手机拇指操作位置调整；标题行沿用列表标题的全宽样式。

## 修复内容

- 新建按钮放到侧栏最后，桌面和手机均固定在底部；历史列表独立滚动。
- 手机使用 52px 高的圆角高对比按钮，并适配底部安全区域。
- 技能区仍可展开和滚动；关闭按钮置于顶部历史标题旁，明确标题可收缩。
- 移动会话更多按钮扩大至 44px，并限制列表滚动向外传播；保留既有抽屉历史与焦点管理。

## 验证结果

- `npm --prefix web-react run build`：通过（含 TypeScript 检查）；既有主包超过 500kB 提示仍在。
- `npm --prefix web-react run test -- ../test/web-react/chat/navigation.test.ts`：4 项通过。
- 本地 Chrome 使用生产构建、模拟 API 和 30 条会话，在 1440×900、390×844、375×667、844×390 检查底部位置、历史滚动、技能展开、新建请求及路由、移动抽屉收起、无水平溢出和无页面异常。
- 首次浏览器启动受沙箱限制，授权后启动成功。早期验证脚本误拦截开发环境 `/src/api/` 模块，改用生产预览；模拟环境禁用 Service Worker 后的提示经关闭后继续验证。
- 未请求真实模型或后端写入；未进行真实手机、iOS 键盘或非零安全区域验证。运行服务未重启，未部署；已本地构建前端资源。

主操作不能随历史列表滚动离开视口。移动抽屉调整后同时检查短屏、长列表、技能展开及关闭按钮触达，不能只依赖 DOM 测试。
