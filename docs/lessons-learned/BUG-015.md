# BUG-015：已用完物品筛选值与后端状态不一致

- 发现日期：2026-10-30
- 状态：已复现，待修复；本次仅修复物品网格布局。

## 现象与影响

点击物品“用完”后，该物品从可用列表移除，但“已用完”筛选无法找到它；全部列表仍可见。

## 复现条件

添加物品，点击“用完”，打开筛选选择“已用完”并应用。

## 排查证据

- 隔离示例服务的 Chrome 验证：7 件可用物品中用完 1 件，可用列表剩余 6 件；“已用完”返回 0 件，全部列表可见 7 件。
- `HomeService.consume_inventory_item` 写入 `status = "used_up"`。
- `InventoryView` 的选项、状态标签和筛选条件使用 `consumed`，筛选条件对 `item.status` 做直接比较。

## 原因

已确认前后端状态命名不一致。其他历史状态或写入路径的兼容范围尚未调查。

## 修复内容

尚未修改；需确定统一状态协议及历史数据兼容策略，再检查编辑、恢复、详情标签和筛选。

## 验证结果

已在临时目录、独立端口的示例服务中复现，未修改用户实际数据；没有进行修复验证、真实模型测试或部署。

## 后续预防

物品状态应使用统一类型和映射；增加从真实消费接口写入到前端筛选展示的流程验证，避免只以模拟 `consumed` 状态测试。
