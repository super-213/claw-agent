# BUG-005：Agent 默认执行预算导致多步任务提前停止

- 发现日期：2026-10-29
- 状态：代码已修复并通过相关回归；运行服务尚未重启

## 现象与影响

用户测试时收到“Agent 执行预算已用尽（steps）：最多 12 步、最长 180 秒、最多 100000 tokens、费用上限 未设置”，要求取消这四项累计执行限制。任务可能在正常工具调用过程中提前停止。

## 复现条件

使用原默认配置运行多步工具任务，持久化的模型/工具步骤数达到 12；时长或 token 用量达到原默认阈值也会触发对应预算中止。原来即使显式把步数、时长配置为 0，也会被构造函数改为 1。

## 排查证据

- `config/settings.py`、`AgentOrchestrator` 和 `RunLimits` 原默认值均为 12 步、180 秒、100000 tokens；费用默认 0。
- `_budget_reason` 原本无条件检查步数、时长，token 和费用则仅在非零时检查。
- 构造函数原使用 `max(1, ...)` 处理步数和时长。
- `_remaining_runtime` 用于模型请求超时和工具执行的剩余预算，单改默认值不足以关闭时长限制。
- 本地 `.env`、`config/.env` 未发现这四项非零预算覆盖；未检查运行进程继承的环境，不能保证现有服务立即使用新值。

## 原因

已确认：默认的有限累计预算会中止正常的长任务，且步数、时长没有提供与 token、费用一致的关闭语义。用户提供的错误文本与源码的 steps 分支吻合；没有读取其私有会话，未认定具体哪次工具调用触发了阈值。

## 修复内容

- 四项累计预算统一默认为 0（不限），同步配置、构造函数、运行限制对象及环境模板。
- 步数、时长允许 0，仅配置正数时执行对应预算检查。不限时 `_remaining_runtime` 返回 `None`，模型不再套用累计时长倒计时，工具保留各自的单次调用超时。
- 保留用正数显式启用预算的能力、用量统计和持久化；提示中关闭的预算显示为“未设置”。
- 保留手动取消、重复调用检测、空回复检测、工具权限、按需加载及 checkpoint 恢复。

## 验证结果

- 执行 `python3 -m pytest -q test/agent_runtime/test_runtime.py test/agent_runtime/test_runtime_v2.py test/agent_runtime/test_tool_loading.py test/test_runtime_api.py`：48 项通过，仅有现存 FastAPI 生命周期弃用警告。
- 新增回归覆盖默认值及显式 0，分别走流式/非流式模型与真实工具执行路径，完成 8 次参数不同的工具调用及最终回答；检查持久化步骤数超过 12、token 超过 100000、费用大于 0、预算值均为 0。
- 累计时长通过替换时钟读数为 1000 秒验证，没有实际等待 180 秒；模型为测试桩，没有发起真实模型或联网请求。
- 显式正数时长/费用预算仍能触发检查；原步数/token 预算、取消、审批、恢复及按需工具加载回归通过。
- `git diff --check` 通过。
- 代码已更新，未重启后端服务，未改写已有 Run 或会话历史。

## 后续预防

关闭累计预算应同时覆盖配置默认值、参数归一化、循环检查、模型等待和工具剩余时间传递。重启服务后新任务会使用新默认值；若部署环境显式配置了非零 `AGENT_MAX_*`，需改为 0 后重新加载配置。
