# BUG-017：账号接口校验失败时回显密码输入

- 发现日期：2026-10-30
- 状态：已复现、代码已修复，账号接口回归通过；运行服务未重启、未部署。

## 现象与影响

核对修改密码的保密边界时发现，密码长度不足或类型错误触发 FastAPI 默认参数校验，422 响应 detail 包含无效输入。密码可能随错误响应被前端调试或代理响应采集系统再次留存。已确认响应回显，未发现或验证实际第三方泄漏，不能据此宣称真实密码已被窃取。

## 复现条件

隔离 TestClient，创建临时示例管理员并登录，对 `/api/auth/change-password` 提交不足 6 位的新密码；检查响应是否包含该示例输入。登录、管理员账号操作等同样使用请求模型校验。

## 排查证据

- 修复前实际输出：`status=422`、`validation_response_contains_password_input=True`，未输出真实密码或原始响应。
- web_app.py 先前只有 HTTPException 和 TaskError 的处理器，未覆盖 RequestValidationError；新密码使用 Field(min_length=6)。
- UserStore 保存随机盐 PBKDF2-SHA256 哈希；正常修改接口仅返回 ok，不返回密码。此次故障在错误响应环节，并非正常持久化保存明文。
- 本次未检查线上反向代理、日志采集平台和实际 TLS 部署，不把这些环节写成已确认安全。

## 原因

已确认：默认请求校验错误详情包含 input；账号接口沿用默认处理，未将包含凭据的输入从错误响应中移除。

## 修复内容

为 `/api/auth/` 和 `/api/admin/users` 范围的 RequestValidationError 返回固定错误码与通用文案，不返回输入、请求体或校验上下文。其他业务接口仍使用原默认校验处理，保留既有字段错误协议。

## 验证结果

- `python3 -m pytest test/test_auth_collaboration.py -q`：12 项通过。新增回归覆盖短密码、额外字段携带敏感值、密码类型错误、登录和创建账号的错误输入以及畸形 JSON；断言响应不含示例凭据，失败不撤销有效登录。
- 既有自身资料权限与持久化、密码更改、全部会话撤销、新旧密码登录回归通过。
- `git diff --check` 通过。
- 首次独立复现脚本从 test 包导入失败；将 test 目录加入模块路径后完成隔离复现。这是脚本导入问题，不是产品原因。
- 无真实模型调用、外网请求或真实用户数据写入；未执行线上代理日志审计、真实 HTTPS 部署验收或 WebAuthn 注册。
- 未重启运行服务，未部署。代码测试通过不代表现有服务已加载修复。

## 后续预防

包含密码、令牌等字段的接口需同时检查成功和校验失败的完整响应；日志不要记录原始请求体或未经脱敏的验证异常。对外部署另需验证 HTTPS、Secure cookie、代理日志策略和访问权限，不以哈希存储替代传输加密。
