# BUG-018：手机历史会话缺少长按操作入口

- 发现日期：2026-10-30
- 状态：代码已修复，14 项定向回归、生产构建及浏览器模拟触摸验证通过；未部署。

## 现象与影响

用户反馈手机端点击历史会话右侧“…”不方便，希望长按会话即可出现复制、共享和删除。

## 复现条件

手机宽度不超过 860px，打开对话历史抽屉，长按一条历史会话。

## 排查证据

- 已确认：`SessionSidebar.tsx` 的会话按钮仅绑定点击打开；菜单只由独立的更多按钮打开，没有长按识别。
- 已确认：既有复制、共享和删除回调可复用，共享和删除已有所有者/管理员权限判断。
- 已确认：既有菜单绝对定位在可滚动列表内，移动端需兼顾列表末端和短屏的可见性。
- 用户触达不便来自用户反馈；未开展真人可用性实验。

## 原因

移动端沿用桌面更多按钮操作，没有提供覆盖整条会话内容区域的长按入口。

## 修复内容

- 移动抽屉中触摸按住会话内容 500ms 打开既有操作菜单；保留桌面和移动更多按钮作为替代入口。
- 位移超过 10px、滚动、抬手、指针取消、离开、关闭抽屉、列表变化或卸载时清除待识别计时器。长按成功后消费松手产生的点击，后续主动短按仍正常打开会话。
- 仅移动会话按钮禁用文本选择及系统触摸弹出菜单，保留纵向滚动。
- 移动菜单在会话下方参与列表布局，打开时滚入可见区域；操作按钮最小高度 44px。
- 复用既有操作及权限判断，没有改变复制语义、共享设置或删除确认流程。

## 验证结果

- `npm --prefix web-react run test -- ../test/web-react/sessions/long-press.test.ts ../test/web-react/chat/navigation.test.ts`：14 项通过，覆盖长按、短按、点击抑制、位移/滚动/取消/离开、关闭及卸载、权限和桌面入口。
- 首次定向测试错误地直接派发 `pointerleave`；React 根据原生 `pointerout` 合成离开事件，修正测试派发后通过。
- `npm --prefix web-react run build`：通过，含 TypeScript 检查；既有主包大于 500kB 提示仍在。
- 临时 Playwright 脚本使用生产资源和模拟 API，在 Chrome 的 390×844、375×667、844×390 上通过 CDP 派发浏览器原生触摸输入，验证长按菜单、松手不请求打开会话、三个操作可见且至少 44px、后续短按正常导航及触摸滑动取消；1440×900 验证桌面更多入口。无页面脚本异常、无水平溢出；检查了 375px 截图。
- 浏览器首次启动受沙箱限制，授权后成功。模拟环境阻止 Service Worker 的应用状态提示曾遮挡测试点击，关闭提示后重新验证通过。
- `git diff --check`：通过。未调用真实模型、未写入真实会话、未验证真实手机及 iOS 系统触摸行为；运行服务未重启，未部署，仅本地构建资源。

## 后续预防

触摸手势增加入口时同时检查短按、滚动取消、系统长按菜单和松手合成点击，不能只验证计时器触发。菜单操作必须复用原权限和业务回调。
