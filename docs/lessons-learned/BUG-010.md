# BUG-010：跨标签退出清理状态后仍停留在原业务页面

- 发现日期：2026-10-30
- 状态：代码已修复，前端全量与生产浏览器缓存/账号隔离验证通过；未部署。

## 现象与影响

将独立离线页改为业务页面自动缓存时，浏览器验证发现：在一个标签页退出登录，另一个标签页接收清理通知后仍可能停留在原业务页面。自动缓存数据需要同时清理持久存储、用户状态及页面显示，不能只删除 IndexedDB。

## 复现条件

同一浏览器登录测试账号并打开两个业务页面。在第二页禁用 BroadcastChannel，验证 localStorage storage 事件的兼容路径。从第一页账号设置退出登录。

## 排查证据

- Chrome 生产构建验收，第一页进入 `/login`，第二页 `wait_for_url('**/login')` 超时。
- 原 App 的 `claw-auth-cleared` 回调只取消同步、将 currentUser 置空并执行 queryClient.clear()，没有显式离开业务页面。
- ProtectedRoute 同时依赖 React Query 查询状态；删除查询缓存并不等同于一次确定的路由跳转。
- 已确认的是回程缺失与测试超时；没有证据表明服务端退出接口允许退出后继续读写，也不将其写成权限绕过。

## 原因

退出的跨标签通知只处理状态清理，没有完整处理当前路由。界面依赖查询状态变化间接触发保护路由，不足以保证立即离开原页。

## 修复内容

- App 收到清理通知后，在取消同步、清理用户和查询状态之外，明确 replace 跳转 `/login`，并清理过期登录弹窗。登录路由不再叠加重认证弹窗。ProtectedRoute 将 React Query 的取消信号传给身份请求，取消的响应不再写回用户状态。
- 本次自动缓存按账号记录 owner，退出/换号及 401/403 清理缓存；请求捕获身份与 generation，阻止退出后的晚到响应写回缓存。其他标签身份与当前持久缓存 owner 不一致时拒绝读取。
- 只在网络失败时使用缓存，不将权限失败、HTTP 错误、请求中止或写入失败伪装为成功。
- 成功写入使对应业务区缓存失效，保留无关页面缓存；存储不可用不阻断联网请求。
- 对话页技能/配置的启动加载改为 allSettled，避免可选技能请求失败阻塞已缓存的对话正文。

## 验证结果

- 最终前端全量 `npm --prefix web-react run test`：24 文件、118 项通过，包含自动缓存专项 9 项。
- 构建（含 TypeScript 与 PWA service worker）、修改文件定向 ESLint 通过；主 JS 大小警告仍在。
- 浏览器已通过原物品页面断网刷新、对话正文离线显示、旧离线路由跳转；首次用例因首页无对应物品、物品名称带数量而失败，改为物品页和包含匹配后通过这部分。
- 完整浏览器验收在通行密钥注册失败：当前 Python 缺少 webauthn，后端返回 500。未修改密钥业务；增加 ROADMAP_SKIP_PASSKEY 可显式跳过该步骤并记录 skipped，使用密码登录继续缓存与账号隔离验收。
- 最终 `ROADMAP_SKIP_PASSKEY=1 python3 scripts/validate_roadmap.py`：通过，包括 390/768/1440 布局、键盘菜单、原物品页面断网刷新、已缓存对话正文、旧路由回程、密码登录、退出/换号、禁用 BroadcastChannel 时跨标签退出、IndexedDB owner 核对、减少动画和无 pageerror。结果文件显式记录跳过 WebAuthn。退出期间晚到的请求返回 401，按实际错误处理，未回退为缓存成功。
- 中间复验还发现，退出后原已过期弹窗未清理，登录页出现两组用户名输入框；补充路由/身份显示条件并取消旧身份请求后，上述最终验收通过。
- `git diff --check`：通过。
- 所有浏览器验证使用本地隔离服务器与示例账号，无真实模型、外网或真实家庭数据写入。代码与构建不代表运行服务部署。

## 后续预防

跨标签退出测试同时检查当前页、其他页、存储 owner 与数据，不以清理函数被调用替代用户可见效果；缓存需验证完整 API 请求路径及生产 service worker 下的断网刷新。保留权限拒绝、换号、晚到响应、写后失效和浏览器配额错误的回归。
