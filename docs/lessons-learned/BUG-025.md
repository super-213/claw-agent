# BUG-025 管理员聊天列表混入无权读取的私有会话

- 发现日期：2026-10-30
- 状态：代码已修复，相关回归与生产构建通过；前端已构建到部署目录，后端已重载

## 现象与影响
管理员对话入口显示“暂时无法打开对话”。健康检查正常时仍无法进入部分会话。

## 复现条件
其他成员创建私有会话后，管理员聊天列表包含该会话；自动或手动选中后详情接口返回 403。浏览器记住的会话不再可访问时也可能触发。

## 排查证据
- 运行服务网站和 API 均返回 200。
- 近期日志包含会话列表 200、详情 403、对应后台任务 404；未保存会话 ID、正文或完整私有日志。
- `_visible_session_metas` 为管理员无条件返回所有元数据；详情使用 `can_read_session`，管理员无权读取他人未共享正文。
- `ChatWorkspace` 自动选择路由、记忆 ID 或第一条会话，失败统一显示打开失败。
- 日志证明存在权限拒绝，无法单凭日志确认用户手机具体选中的会话；代码矛盾已由接口回归复现。

## 原因
管理统计元数据的可见性被复用到聊天会话列表，与正文读取权限不一致。并非健康检查失败或管理员缺少系统角色。

## 修复内容
- 会话列表使用 readable_only 过滤，管理员也仅列出自己或被共享的会话。
- 统计相关调用保持原元数据范围，正文权限不放宽。
- 自动恢复仅使用当前列表包含的记忆 ID；明确直达链接的 403/404 提示选择其他会话或新建，保留输入。
