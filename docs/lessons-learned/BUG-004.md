# BUG-004：留言板聊天回归未隔离意图模型

- 发现日期：2026-10-29
- 状态：测试已修复；不涉及运行服务更新。

## 现象与影响

插件迁移相关回归第一次全部通过，最终复跑时，留言板原生工具用例没有生成卡片。该用例只替换聊天模型，却仍可进入单独的意图模型路径；存在外部请求和结果不稳定风险，不能把这类回归视为纯本地验证。

## 复现条件

运行 `test/test_board.py::test_native_chat_cards_and_real_receipt[False]`，使用原 `board_api` fixture，真实环境配置允许意图模型返回家庭服务意图。

## 排查证据

- 首次相关合并运行 126 项通过。
- 再次运行出现 127 项通过、1 项失败；失败事件 `source=llm:home`，没有进入预定的 `family_board_post_create` 工具链。
- `board_api` 继承家庭 API fixture，替换业务存储；具体用例仅替换 `_new_llm_client`。
- 意图路由器是独立全局对象，其模型工厂不随 `_new_llm_client` 的替换而自动改变。

## 原因与未确认项

已确认：测试未替换意图路由，生产意图路径能够抢先产生 direct_response，绕过该测试期望的聊天工具执行。

未确认：本轮没有记录意图接口请求次数与响应原文，不推断具体模型、供应商或调用计费；不把这次非预设路径作为真实模型验收，不保存私有响应。

## 修复内容

只在 `board_api` 测试 fixture 中把意图路由固定为 `general_chat`，明确测试原生工具、权限、卡片与持久化。意图路由自身测试由独立的 `test/services/test_intent_router.py` 负责，不改生产路由逻辑。

## 验证结果

修复后相关后端回归 128 项通过（5.96 秒），结果见 `docs/015-tool-plugin-architecture-plan.md` 第 11 节。插件专项 17 项使用模拟 SDK 响应完成；未安排真实模型验收，未重启运行服务。

## 后续预防

集成测试应分别隔离意图模型与聊天模型。fixture 除了替换存储，也要清楚标注是否允许外部模型/网络请求，不能只凭最终回答正确判断原生工具链已验证。
