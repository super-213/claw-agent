# BUG-014：家庭物品单列布局浪费宽屏空间

- 发现日期：2026-10-30
- 状态：代码已修复；构建、首页回归和浏览器布局验证通过，未部署。

## 现象与影响

家庭物品页每件物品横跨整行，名称与“用完”按钮距离过远，横屏无法并排展示多件物品。

## 复现条件

打开 `/home/items`，在桌面或横屏设备查看有物品的存放位置；单件和多件物品均占满整行。

## 排查证据与原因

- 用户截图显示单件物品的标题区域延伸至页面右侧。
- `InventoryView.tsx` 原先使用通用 `.home-list`，没有网格列定义；`.home-list-item` 作为块级 flex 容器占满可用宽度。
- 这是已确认的页面布局问题，不涉及物品查询或模型工具协议。

## 修复内容

- 仅给物品列表增加 `inventory-grid`，使用 `auto-fill` 按容器宽度排列，列最小宽度 280px，容器不足时收缩为单列。
- 使用 `auto-fill` 保留空列，使仅有一件物品时也不会拉伸到整行。
- 为每件物品设置边框、内边距和圆角，将详情入口与“用完”操作放在同一卡片中。
- 保留名称自动换行、原有详情与写入操作；不修改其他列表。

## 验证结果

- `npm --prefix web-react run build`：通过，包含 TypeScript 检查；有现有的大体积 JS chunk 提示。
- `npm --prefix web-react run test -- test/web-react/home/home-page.test.ts`：10 项通过。
- 在 `home_workbench_server.py` 创建的临时目录和独立端口上，使用 Chrome/Playwright 验证单件不撑满整行、多件排列及中英文超长名称。
- 1440/1024/844/768/390/320px 分别为 4/3/2/2/1/1 列，无卡片或页面横向溢出；详情、用完后移出可用列表、全部筛选通过，无页面 JS 异常。
- 浏览器中发现既有“已用完”筛选问题，单独记录为 BUG-015；不能宣称此筛选通过。
- 首次 Chrome 在沙箱中启动失败；扩大权限后运行。中途带批量清理意图的验证命令被自动审批拒绝，未执行该清理；随后完整检查脚本，改用隔离服务的空冷冻室追加数据，验证成功。
- 最后增加网格顶部对齐后重新构建通过；浏览器检查未单独断言卡片高度或顶部对齐。
- 未调用真实模型或外部业务接口，未修改用户实际数据。代码与构建产物已更新，未部署，也未重启用户运行中的服务。

## 后续预防

物品布局使用独立样式，避免修改共享列表影响事项及操作记录。布局验证覆盖单件、多件、宽窄容器和长名称，不仅检查 DOM 数量。
