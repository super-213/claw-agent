# BUG-030：活动历史清理把 macOS 元数据作为 JSON 读取

- 发现日期：2026-11-05
- 状态：代码已修复，相关回归通过；正式托管后端已启动并加载修复。

## 现象与影响
后台每隔约 10 秒输出 `[activity_lifecycle] UnicodeDecodeError`。生命周期循环遇到异常会跳过后续历史清理及通知投递，下一轮继续重试；普通 API 仍可返回 200。

## 复现条件
存在已不可访问的活动，且会话或 Run 目录含 `._*.json` AppleDouble 二进制元数据文件。清理使用 `glob('*.json')`，其结果包含隐藏文件。

## 排查证据
只读检查真实目录：会话目录中两个 UTF-8 解码失败的文件均以 `._` 开头，前四字节均为 AppleDouble magic `00051607`；Run 目录未发现解码失败。未保存文件名、正文或完整私有会话。普通会话列表已跳过隐藏文件，但活动清理没有相同过滤。

## 原因
已确认该清理路径会读取匹配的二进制元数据，并可用合成文件复现相同异常。原运行日志只有异常类型，没有堆栈，不能证明全部历史同名异常都源于此处。

## 修复内容
Run 与会话扫描跳过隐藏文件和非普通文件。真实 JSON 文件解码失败仍然报错，不吞掉数据损坏；不删除真实数据或系统元数据。

## 验证结果
新增合成 AppleDouble 与真实记录混合目录回归：元数据保留、两类真实历史记录完成净化；真正损坏的非隐藏 JSON 仍抛出 UnicodeDecodeError。与启动脚本及完整家庭活动测试一起执行，24 项通过。首轮测试替身没有实现 ConversationStore 的持久化净化回调，导致断言失败；补齐替身后通过，业务实现未为此修改。无真实模型或外部联网验证，未在生产执行清理，未重启服务。

## 后续预防及相关代码
扫描目录时显式定义业务文件范围；在 macOS 回归中包含 AppleDouble 文件，不能用忽略全部解码异常的方式掩盖真实数据损坏。
相关：`services/family_activity_privacy.py`、`services/conversation_store.py`、`test/services/test_activity_history_metadata.py`、`test/test_family_activities.py`。
