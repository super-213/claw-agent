# BUG-023 创建用户与家庭成员绑定脱节，未绑定提示不明确

- 发现日期：2026-10-30
- 状态：代码已修复；定向前端回归及生产构建通过；未部署

## 现象与影响
新账号可登录，但家庭数据请求失败，首页仅提示部分数据无法读取。管理员创建用户时无法同时绑定家庭身份。

## 复现条件
创建启用账号但不通过家庭成员管理绑定；登录后进入首页。

## 排查证据
- `UserAdminModal` 原先只调用账号创建接口。
- `FamilyMemberService.actor` 对未绑定账号抛出 `member_not_bound`（403）。
- 物品接口通过 `require_home_member` 检查绑定；首页原先将查询错误统一呈现为读取失败。
- 上述为代码确认；未读取线上账号或请求日志，不能确认用户线上失败全部由此导致。

## 原因
账号与家庭身份分离，但创建流程缺少绑定选项，首页也未区分授权原因和其他读取错误。

## 修复内容
- 新建账号默认同时添加家庭成员，可改选未绑定有效账号的已有成员，或仅创建账号。
- 复用管理员专属绑定接口；绑定已有身份时只更新账号与启用状态，保留姓名、别名及成员 ID。
- 成员列表加载失败时禁止带绑定创建；禁用账号仅允许单独创建。
- 分两步调用接口：账号创建成功后绑定失败，保留新账号 ID、清空密码，明确提示部分成功并提供重试绑定，不重复创建账号。
- 首页及家庭子页识别 `member_not_bound`，提示管理员绑定路径与刷新操作。
- 更多管理员工具补充用户管理入口。

## 后续预防
跨资源创建应明确部分成功状态与可恢复操作，不能将已创建账号当成失败后重新创建。授权错误应显示具体原因，保留成员与账号的显式绑定约束。
