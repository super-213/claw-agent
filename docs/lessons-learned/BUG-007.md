# BUG-007：分支会话显示技能已加载，但完整说明没有进入模型请求

- 发现日期：2026-10-29
- 状态：代码已修复，SDK 请求与相关回归已验证；运行服务尚未重启。

## 现象与影响

接入 `$ 技能名 任务` 显式调用时，Web 聊天会发出技能已加载事件，但最终 SDK 请求不含该技能的完整说明。模型可能只能看到目录摘要，无法按显式技能的完整步骤工作。

## 复现条件

使用带 BranchEngine 的 Web 会话，注册带有唯一说明文本的技能，再经流式或非流式聊天显式选择该技能。只检查无分支 ConversationManager 或加载事件无法复现完整故障。

## 排查证据

- `test/test_skill_chat_api.py::test_registered_skill_list_and_explicit_context_reach_sdk` 的两个聊天路径首次均失败：`run_status=completed`，控制台打印技能已加载，但捕获的 SDK messages 中找不到唯一技能说明。
- `inject_skill_context` 原来调用 `add_system_message`，只追加到 `_messages`。
- `get_messages` 及编排器在有分支时取 BranchEngine 活跃路径，技能说明没有对应节点，因此被遗漏。
- 以上为请求与代码执行证据；没有使用模型自我解释作为原因。

## 已确认原因

技能注入沿用线性消息列表，Web 请求组装使用分支路径，两种上下文存储没有同步。故障发生在模型请求准备阶段，并非模型不选择工具或工具执行失败。

## 修复内容

`ConversationManager.inject_skill_context` 在存在分支时追加真实 system 节点并移动活跃节点，同时保留线性模式兼容。没有扩大工具或目录权限。

## 验证结果

- 新增流式/非流式 Web 测试，核对最终 SDK 的技能说明、清理后的用户请求、技能目录 API 和持久化 Run 的 active_skill；修复后两个路径通过。
- 原生调用回归覆盖 `tool_load → skill_install → 确认恢复 → skill_load → 最终回答`，包含模拟 SDK 的真实请求序列和持久化检查。
- 功能开发中曾因 HTTP 响应上限参数替换误影响 `_file_read` 而出现一项回归失败；已恢复文件读取的独立上限，相关回归通过。
- 有限真实公网验证：4 次请求从公开 GitHub 技能目录下载两个文件，临时目录注册与读取成功后清理；未执行来源脚本。
- 相关后端回归 242 项通过；前端完整回归 102 项通过，类型检查、ESLint 和生产构建通过。后端含现有 FastAPI 弃用及旧测试 return 值警告；构建有现有 bundle 大小提示。
- 未调用真实模型，没有重启运行服务。

## 后续预防

新增显式技能入口时必须验证最终 SDK messages，覆盖分支与持久化；不能将加载事件或线性上下文单测通过视为完整请求链路已验证。
