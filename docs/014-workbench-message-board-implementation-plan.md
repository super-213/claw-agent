# 工作台留言板与共享便笺实施计划

日期：2026-10-27  
状态：P0–P3 已实施，验证结果见第 10 节。  
范围：在工作台中部增加与「我的小组件」平级的留言板，以拟物便笺承载文字、图片、共享范围与有效期；支持手动创建和 Agent 对话中的交互式配置。

## 1 目标与范围

工作台现有中部结构为「家庭助手输入区 → 状态反馈 → 我的小组件」，右侧是家庭日历。本轮只调整小组件所在的内容区域：增加「小组件 / 留言板」切换入口，两者占用同一层级和区域。家庭助手输入区、侧边导航、右侧日历及现有小组件能力继续沿用。

用户可以发布一张固定大小的纸质便笺，写文字、放图片，分享给一个人、多个人或所有人。内容过长时在便笺内部滚动，也可以点击进入详细查看，通过点击周围空白或返回按钮退出。便笺支持长期保留或设置有效期，既能手动配置，也能让 Agent 根据自然语言创建，再通过交互卡片调整。

### 1.1 用户已明确的要求

| 要求 | 落地行为 |
| --- | --- |
| 留言板与小组件平级 | 同一区域通过按钮切换，留言板不作为一个小组件插入网格 |
| 拟物便笺 | 参考用户截图及指定网站的纸张、阴影、虚线分隔和打字机排版 |
| 单人、多人、所有人共享 | 成员选择器与 `@ XXX`、`@ XXX @ YYY`、`@ 所有人` 均可表达接收范围 |
| 文字与图片 | 支持纯文字、纯图片和图文混排，图片可预览 |
| 便笺固定大小 | 列表内不随内容长度增高，正文区内部滚动 |
| 详细查看与退出 | 点击便笺打开详情；点击遮罩空白、返回按钮可退出 |
| 长期或限时 | 创建和编辑时均可手动配置 |
| Agent 协助创建 | 对话中理解内容和共享对象，返回可交互配置卡片 |
| 承接上一轮日程、备忘 | 复用 013 已落地的通用交互卡片协议与状态管理 |

### 1.2 首版建议与边界

以下为本计划的实施建议，区别于用户已明确的要求，后续可在实施前调整：

- 「所有人」定义为当前家庭中账号有效且已绑定的成员，不扩展为整个部署的所有注册用户或公网访问者。后续加入家庭的有效成员也能看到仍有效的全员便笺；指定共享使用固定成员 ID 集合。
- 未选择接收人时保留为仅作者可见的草稿，不默认向所有人发布。选择接收范围后即可发布。
- 长期保留表示不设置自动到期时间；限时便笺到期后自动销毁，不保留过期历史。便笺正文、关联草稿副本、备份中的过期内容与无其他引用的图片按第 12 节清理。
- 作者可编辑、调整共享与有效期、撤下便笺；接收人只读。首版不包含回复、评论、点赞、已读回执和内容置顶；根据第 11 节的反馈，现支持便笺自由拖放、重叠及点击提升显示层级。
- 首版不新增主动通知；「共享成功」表示已可在对方留言板查看，不声称已送达、已读或已主动提醒。
- 保留现有事项、日历和备忘的独立语义。留言板不自动把一句留言转成任务，也不因便笺过期改变已有日程。

## 3 工作台布局与切换

建议在原小组件标题位置设置一组分段按钮：

```text
家庭助手输入区
状态反馈

[ 我的小组件 | 留言板 ]                  当前视图操作

小组件视图：现有组件网格                  自定义
留言板视图：纸质便笺网格                  写便笺
```

- 首次进入默认显示「我的小组件」，后续按账号记住最近一次选择；建议使用独立的 `claw.home.panel.v1.<userId>` 偏好键，不修改已有 widget 存储格式。
- 「自定义」仅在小组件视图出现；「写便笺」仅在留言板视图出现。切换按钮在两种视图中保持同一位置。
- 留言板默认显示当前账号有权限读取的有效便笺，按发布时间倒序排列，使用稳定 ID 作排序补充；编辑不改变原发布时间。
- 不提供来源、状态筛选；服务端统一返回自己创建、别人 @ 自己和 @ 所有人的有效便笺，不在前端下载其他人的内容再隐藏。
- 切换保留各自滚动位置与筛选；小组件自定义中的临时状态按现有规则处理，便笺未保存表单不能静默丢失。
- 从聊天中的「在留言板查看」返回工作台时直接切换到留言板并定位该便笺；其他普通聊天操作不强制切换视图。
- 留言板加载失败不阻塞助手和小组件；区分加载、空列表、读取失败和有旧数据但更新失败，提供局部重试。

## 4 便笺视觉与阅读交互

### 4.1 参考与样式

参考来源为用户提供的两张截图，以及 [复古打字机便笺参考页面](https://llm-chat-app-template.zhihaojiangzhj.workers.dev/)。已读取参考页面 HTML/CSS：便笺使用白色直角纸张、柔和投影、头尾虚线分隔、等宽字体与内部滚动正文。借鉴顶部拖动与纸张摆放，不引入整页打字机或悬浮放大。自由摆放及移动端方案见第 11 节。

建议留言板局部使用柔和灰色桌面底，便笺采用白纸或暖白纸，低强度纸张质感和投影。头部显示作者、发布时间；底部显示接收范围、长期/截止时间和「查看详情」。保留虚线分隔，避免为了装饰塞入参考图中的英文结束语。

中文正文使用易读的中文字体，英文和数字可使用打字机风格等宽字体；不以字间距或手写字体牺牲长中文阅读。暗色主题使用适配后的纸张与桌面颜色，保持文字对比度，样式限定在留言板模块内。

### 4.2 固定尺寸与内部滚动

- 桌面便笺建议初始尺寸为 `280 × 320 CSS px`，所有便笺一致，不跟随图片比例或正文长度变化。尺寸是设计起点，实施时可整体调整。
- 使用固定头部、可滚动正文、固定底部三段布局；正文设置 `min-height: 0`、`overflow-y: auto` 和长单词折行。头尾元信息不随正文滚走。
- 初次出现的便笺填入空位，随后可通过顶部拖动把手自由摆放、重叠；不强制吸附到网格。点击或键盘聚焦将对应便笺提升到最上层。
- 手机默认双列、固定 210px 高度的缩略便笺，展示作者、标题、摘要和共享信息，轻点进入完整详情；可切换到可缩放、平移和拖放的同一画布。页面不产生横向溢出，画布内部独立滚动。
- 图片按正文宽度等比展示，设置预留尺寸避免加载跳动；大图不撑开便笺外框。失败时显示可重试占位。
- 鼠标滚轮、触控滑动、键盘均能滚动正文。滚动或选择文字不触发详情；图片点击打开图片预览，编辑按钮只执行对应操作。
- 便笺提供明确的「查看详情」按钮及键盘入口。主体非交互空白处也可打开详情，但不把带滚动区和多个按钮的整张便笺嵌套成一个大按钮。

### 4.3 详细查看

桌面点击便笺后打开居中的纸张详情与遮罩，展示完整图文、作者、共享对象和有效期；正文可随视口滚动。进入详情时查询最新数据与权限，不直接相信列表快照。

退出方式包括点击详情周围的遮罩空白、点击「返回留言板」、按 Esc、浏览器返回。点击纸张内部和操作按钮不误关闭。关闭后回到原列表位置，并将焦点还给原便笺入口。

手机使用带返回按钮的近全屏详情；保留可用遮罩区域时同样支持点击退出。图片预览在详情上方另开一层，返回优先关闭图片层，再关闭便笺详情。复用现有 `HomeDialog` / `useDialog` 的焦点约束与返回处理，避免多层覆盖时把整页退出。

阅读态点击空白直接关闭；进入编辑后关闭时保留未提交输入，必要时提示保存或放弃。切换账号或退出登录清理表单和可见数据。

## 5 共享、内容与有效期

### 5.1 共享规则

| 范围 | 谁能读取 | 谁能修改 |
| --- | --- | --- |
| 未发布草稿 | 作者本人，且聊天草稿受原会话/分支约束 | 作者本人 |
| 指定一人或多人 | 作者及被选中的有效家庭成员 | 作者本人 |
| 所有人 | 当前家庭所有有效成员 | 作者本人 |
| 已到期 | 自动销毁，无人可继续读取 | 不可修改或恢复 |
| 已撤下 | 仅作者可查看撤下记录 | 首版只读，不自动恢复发布 |

`@` 表示接收对象和读取范围，不代表任务负责人，也不授予接收人编辑权限。选择「所有人」与指定成员互斥，重复成员去重；移除「所有人」标签后必须重新选择接收人才能发布。

移除某接收人后，其列表、详情、聊天卡片和便笺媒体入口均失去访问权。成员被停用时即时拒绝读取和写入；技术管理员身份不自动获得指定共享便笺的读取权。可见范围扩大时展示新增可见对象，用户保存该变更即表示明确选择新的共享范围。

共享会话还需考虑会话读者：若会话范围超过便笺范围，不在消息正文或卡片中泄露指定共享内容，引导作者到个人对话配置。便笺共享不会自动共享原聊天；引用不带私人会话正文、原始工具参数或私人会话链接。

### 5.2 内容与图片

- 正文建议采用有序的 `text` / `image` 内容块，保留图文顺序。标题可选；至少包含一段非空文字或一张已上传成功的图片。
- 手动创建支持选择图片、粘贴图片、移除图片和调整内容顺序。建议首版限制为文字总长 10,000 字、最多 9 张图、单图 10MiB，并由服务端统一校验、前端提前提示。
- 首版支持经解码校验的 JPEG、PNG、WebP；文件扩展名和客户端 MIME 不能替代校验，不接受可执行 HTML/SVG 内容。
- 上传不等于发布。上传失败时保留文字输入，标明未成功图片；不悄悄丢图后宣称整张便笺已保存。
- Agent 只能引用当前用户有权访问、且用户选定用于本张便笺的附件，不虚构图片地址、不自动公开整段会话中的其他图片。
- 发布时将选中图片保存为独立的便笺资产，使用资产 ID 与便笺权限控制访问；聊天清理不能使长期便笺丢图。复用上传校验，不能直接依赖原会话授权或公开静态路径。
- 原聊天文件的权限继续由原聊天决定；便笺收回共享控制的是便笺资产及其入口，不能承诺收回对方已经下载的副本。

### 5.3 长期与限时

| 模式 | 配置 | 展示与到期行为 |
| --- | --- | --- |
| 长期保留 | `expires_at=null` | 持续出现在有效列表，直到作者撤下 |
| 限时保留 | 具体截止日期与时间 | `server_now >= expires_at` 时不可再读写，并自动销毁 |

手动配置提供「长期保留 / 限时保留」，限时模式支持快捷时长和自定义日期时间。建议默认长期保留，并在发布前清楚展示；用户明确选择限时却没提供截止时间时保持草稿，不能降级为长期。

截止时间以家庭时区解释，界面显示时区与完整日期时间，服务端保存带时区的时间点并统一比较。仅给日期时建议解释为当地次日 00:00 到期，并在卡片展示这个实际截止时间；「保留 24 小时」以实际发布成功时间为起点，「明晚结束」等绝对截止在草稿中解析后不随重试漂移。

到期状态由服务端每次读取与写入时计算，不能依赖用户电脑时间、前端计时器或后台清理是否运行。响应返回 `server_now`、`valid_until`、`next_transition_at` 与动作能力；页面到达边界、重新聚焦或恢复网络时刷新。所有写入口在实际事务中再次校验到期状态。

到期前作者可延长或缩短有效期、改为长期；设置已过去的截止时间应拒绝并提示使用「撤下」。到期便笺不通过旧聊天、改日期、恢复草稿或重试请求重新变为有效。需要再次发布时，由用户明确重新提供内容并创建新便笺；到期清理由独立后台任务及读写入口共同执行。

## 6 手动创建与 Agent 交互卡片

### 6.1 手动流程

1. 点击「留言板 → 写便笺」，打开编辑器。
2. 输入文字、选择图片，选择一个或多个接收人，或选择「所有人」。
3. 选择长期或限时，预览纸张内容、接收范围及截止时间。
4. 点击「发布便笺」，服务端一次校验并保存，成功后进入留言板。
5. 作者在详情点击「编辑」修改原记录；接收人仅看到阅读入口。撤下使用独立动作，保留作者历史。

### 6.2 Agent 自然语言与 @ 入口

支持用户所描述的三类输入，以下例子均在「写便笺」上下文或明确留言意图下解释：

```text
单人：@ XXX 我要告诉你，今天晚饭在冰箱里，帮我留张便笺。
多人：@ XXX @ YYY 我要周末整理储物间，帮我发一张便笺，保留到周日晚上。
所有人：@ 所有人 我要分享这张照片，放到留言板，长期保留。
```

- 输入 `@ ` 时显示当前家庭有效成员及「所有人」，选择后绑定真实成员 ID；支持多人标签和删除标签同步撤销选择。
- 不要求额外输入斜杠命令。普通自然语言如「给妈妈留张便笺」也可解析；别名、同名或无法确定对象时在卡片中选择，不能由模型编造成员 ID。
- 在普通聊天中，仅出现 `@ XXX 我要……` 且意图不清楚时给出便笺草稿或轻量选择，不直接发布。明确要求记录日程、备忘的请求仍走原事项能力，不能被留言板解析抢占。
- 共享对象与有效期优先取用户本次明确选择；用户后来明确修改时更新同一草稿，不丢失图片和其他已配置项。
- 自然语言中的时间不一概当成便笺到期时间，例如「明天聚餐」可能只是正文；「这张便笺保留到明晚」才明确指向有效期，无法判断时由交互卡片补充。

### 6.3 草稿、发布与后续配置

复用 013 的「工具结果 → 服务端引用 → 通用容器 → 业务适配器」链路，新增 `kind=board_post`；已发布资源为 `board_post`，草稿资源为 `board_post_draft`。

| 用户意图/状态 | 工具行为 | 卡片行为 |
| --- | --- | --- |
| 「帮我写一张……」，尚未要求发布 | 保存草稿 | 显示「未发布」，可编辑并点击「发布便笺」 |
| 明确发布，正文、对象与有效期均可确定 | 创建真实发布记录 | 显示「已发布」，支持继续调整原记录 |
| 缺接收人、图片未就绪或限时缺截止 | 返回草稿和待补充字段 | 可选择成员、补图、补时间，再发布 |
| 查询已有便笺 | 读取当前授权记录 | 显示最新内容、版本、时效和动作能力 |
| 用户要求修改或撤下 | 查询后对原 ID 执行动作 | 同步更新原卡片与留言板，不另建副本 |

卡片至少包含正文编辑、图片预览/增删、共享方式、成员多选、长期/限时、截止时间、真实状态及操作按钮。按钮直接调用认证业务 API，不再请求模型解释一次。

明确发布请求在字段齐全时无需额外强制确认；用户正在草稿卡片中配置时，点击「发布便笺」即完成提交。未发布、保存失败、网络结果未知分别展示，不能以模型回复替代真实回执。

聊天仅持久化轻量卡片引用和来源；每次重新打开查询真实记录。流式、最终消息、后台完成和会话恢复合并同一 `card_id`。删除聊天不删除已发布便笺；撤下便笺后旧卡片同步隐藏接收人的内容。不能依赖历史消息中的正文快照继续展示已经撤权的数据。

## 7 数据、API 与权限实现

### 7.1 独立便笺领域

建议增加 `BoardPostService` 和独立存储 `board.json`，按项目现有家庭数据目录组织；具体类名在实施时确定。便笺领域拥有内容、共享、发布和有效期规则，通用交互卡片只负责展示、请求和刷新。

| 字段 | 含义 |
| --- | --- |
| `id / household_id / created_by` | 服务端生成的便笺 ID、家庭边界、作者身份 |
| `title / content_blocks` | 可选标题和有序图文块，图片引用 `asset_id` |
| `audience_mode / recipient_ids` | `selected / household`；指定模式下的去重成员 ID |
| `retention_mode / expires_at / timezone` | `permanent / until`，截止时间与家庭时区；相对时长在发布事务内结算 |
| `publication_state` | `published / withdrawn`；过期为根据时钟计算的状态 |
| `created_at / published_at / updated_at / withdrawn_at` | 审计时间；编辑不改变首次发布时间 |
| `version` | 乐观并发版本号 |
| `resource_refs` | 预留已授权业务资源引用，首版为空 |
| `source` | 内部记录手动/Agent 来源、运行与工具关联，不作为对接收人的会话入口 |

草稿单独存储 `draft_id`、作者、会话/分支、配置、版本、草稿失效时间和提交结果。草稿 TTL 不等于已发布便笺有效期；TTL 长度复用现有草稿策略并由服务端返回。资产记录保存便笺关联、文件信息与校验结果，不把 base64 图片塞入账本或消息引用。

### 7.2 拟定接口与工具

| 接口 | 用途 |
| --- | --- |
| `GET /api/home/board/posts` | 按当前账号、筛选和游标分页读取可见便笺 |
| `POST /api/home/board/posts` | 手动或 Agent 发布字段完整的便笺 |
| `GET /api/home/board/posts/{id}` | 详情与最新授权数据 |
| `GET /api/home/board/posts/{id}/card` | 交互卡片视图、版本、服务端时钟与动作能力 |
| `PATCH /api/home/board/posts/{id}` | 作者原子更新正文、共享及有效期 |
| `POST /api/home/board/posts/{id}/withdraw` | 作者撤下 |
| `POST /api/home/board/drafts` | 保存未发布配置 |
| `GET /api/home/board/drafts/{id}` | 读取当前作者及分支有权访问的草稿 |
| `PATCH /api/home/board/drafts/{id}` | 保存草稿配置 |
| `POST /api/home/board/drafts/{id}/commit` | 校验配置后一次发布，返回同一草稿的提交结果 |
| `POST /api/home/board/assets` | 上传或从已授权聊天附件导入候选资产 |
| `GET /api/home/board/assets/{id}` | 依据当前便笺/草稿权限返回图片字节 |

建议原生工具为 `family_board_post_create/get/list/update/withdraw` 及草稿接续工具。工具复用同一便笺服务和认证上下文，不通过通用文件工具改账本，也不提供假成功占位工具。图片只接受可验证附件/资产引用，创建工具根据缺失字段返回草稿或真实记录。

所有写请求携带稳定 `request_id`，编辑带 `expected_version`；同一次重试保持相同请求 ID 和参数。服务端在事务内处理权限、版本、时效、幂等回执和业务变更，重复发布不生成多张便笺，重复撤下也不重复变更。

版本冲突保留用户输入并提示加载最新版本，不静默覆盖。网络超时显示「结果待核实」，先按原请求 ID 核实再允许重试；已成功发布的请求即使跨过到期边界也只返回原结果及当前状态，不重新发布。

### 7.3 媒体、缓存与同步

- 上传候选资产仅作者可见；发布事务验证所有资产都属于本次授权输入，并将引用一起提交。文件先落盘、账本再提交，失败产生的未引用文件通过受控回收处理，不能留下公开图片。
- 便笺图片走受保护的资产路由，不放到现有可由上传者目录直接读取的普通生成文件路径中作为共享方案。缩略图与原图执行相同权限校验，撤下和移除接收人立即影响后续读取。
- 列表、详情、草稿、卡片和图片权限由服务端统一检查，操作者来自登录身份。不存在和无权读取采用不泄露对象存在性的错误响应；模型、请求正文和 `surface` 均不能授予权限。
- 便笺 API 与受保护媒体不进入 PWA 离线缓存；响应设置私有数据缓存策略。登出、切换账号、授权失败时清理查询缓存、图片对象 URL 和编辑状态。
- 发布/编辑/撤下后发出沿用公共协议的 `resource_changed`，按 `board_post` ID 失效聊天卡片、列表和详情。当前页面事件用于本端同步，其他账号依靠重新聚焦刷新及留言板可见时的轻量轮询获取更新；首版建议间隔 30 秒，隐藏时暂停。
- 到期边界单独依据服务端时钟刷新，不能等待轮询才阻止写入。离线时保留本次输入并显示无法保存，不自动后台发布；恢复网络先核实权限、版本和时效。

6. 图片预览与便笺详情返回顺序正确；关闭后保留列表筛选、位置并恢复焦点；手机、键盘与文字放大可用。
7. 纯文字、纯图片和图文顺序保存正确；上传失败保留输入且不显示整张发布成功，非法类型和超限内容被服务端拒绝。
8. 使用作者 A、接收人 B、未被选中的成员 C 验证指定共享：B 可读，C 的列表、详情、卡片、缩略图和原图均不可读。
9. 多人共享去重，「所有人」与指定成员互斥；全员范围只覆盖当前家庭有效成员，停用账号和技术管理员不能越权。
10. 改为指定共享或移除 B 后，B 的旧链接、旧聊天卡片和媒体请求失去权限，前端刷新后不继续呈现缓存正文。
11. 长期便笺跨日仍有效；限时便笺在边界时刻退出有效列表，历史只读且图片规则一致，不被当成任务完成或删除。
12. 服务端家庭时区与浏览器时区不同时显示与到期仍正确；相对时长从成功发布时起算，绝对截止不因草稿重试漂移。
13. 绕过前端调用编辑、工具或草稿提交接口，均无法修改过期原记录或借旧引用重新发布；复制重发必须明确产生新记录。
14. 手动与 Agent 均可配置正文、图片、单人/多人/所有人、长期/限时；日程和备忘原有自然语言路径不被抢占。
15. 意图仅为代写、接收人不明确或限时缺截止时返回未发布卡片；用户在卡片补充后一次发布；明确且完整的发布请求可直接成功。
16. 聊天中的卡片编辑更新原便笺，留言板和其他展示同步；流式、最终消息与会话重开不产生重复卡片或重复记录。
17. 图片独立于原聊天持久化；清理会话后长期便笺仍可读图，发布便笺不暴露私人聊天或其他未选择附件。
18. 重复点击、请求超时重试、后台完成、刷新恢复和版本冲突不重复发布、不覆盖他人已保存版本；未核实结果不报成功。
19. 共享会话不能泄露范围更小的便笺；未授权媒体直链、伪造作者/成员/家庭、跨账号草稿引用均被拒绝。
20. 登出和账号切换清理内容与表单；离线不自动发布，重新联网先核实版本、权限和到期状态。

验证安排：后端重点测试权限矩阵、资产生命周期、到期事务、并发与幂等；前端验证切换、固定尺寸、正文滚动、卡片配置和多层返回。浏览器至少覆盖 1440px 桌面与 390px 手机、明暗主题、不同浏览器时区，并以隔离测试账号完成真实跨成员流程。实施结束后在本文追加实际测试和截图位置；本次计划阶段不宣称这些检查已经通过。

### 11.1 桌面自由画布

- 顶部作者栏及其下方虚线是拖动区域，显示抓取指针与拖动标识；正文继续用于阅读和内部滚动，底部按钮用于打开详情。拖动不误开详情。
- 使用 Pointer Events、指针捕获和抓取偏移；超过 5px 才提交移动意图，通过动画帧按鼠标/手指位移更新，缩放时换算为画布坐标，保持跟随。到边缘可以自动滚动画布。
- 便笺可在任意坐标重叠，不强制吸附或避让；按下或聚焦露出的便笺即提升层级，层级隔离于弹窗之外。
- 鼠标拖动画布空白可平移；滚轮、滚动条及触控支持画布内滚动。提供放大、缩小、适应宽度和「整理」入口；整理仅重排当前筛选出的便笺。
- 方向键以 10px 微调，Shift + 方向键移动 40px，Esc 取消本次拖动并恢复位置。减少动态效果设置下仍保留直接跟随与静态反馈。
- 布局按 `claw.board.layout.v1.<userId>` 保存到当前浏览器，只保存便笺 ID、坐标与显示层级；不包含正文，也不改动共享业务记录。刷新、过滤和新增便笺不重置已保存位置；不同账号互不覆盖。

### 11.2 手机与小屏

- 小于 768px 默认双列缩略总览，每张 210px 高；将完整正文、长截止时间和图片阅读放到详情，避免一张便笺撑满留言板。
- 「总览 / 画布」切换只改变展示方式，保持同一批便笺与桌面摆放坐标。总览不覆盖手动摆放结果。
- 画布默认缩小展示，提供可点击的缩放控件；空白区域触控平移，顶部抓取区域触控移动便笺；详情仍提供完整图文、图片预览及原有返回方式。
- 明暗主题分别适配纸张、文字、虚线与画布点阵。画布内部允许横向滚动，整个页面不产生横向溢出。

## 12 自动可见范围与到期销毁（2026-10-27，当前规则）

本节按最新反馈替代前文历史实施记录中的来源/状态筛选与过期只读历史规则。

- 移除「全部可见」「有效」两个下拉框，不提供其他手动过滤入口。每个账号自动看到自己创建、其他成员指定给自己、以及当前家庭所有人的有效便笺。
- 服务端列表与 Agent 查询使用相同的固定可见规则；即使旧客户端带上过期/撤下筛选参数，也不能取回被销毁内容。撤下便笺不进入默认留言板。
- 到期立即禁止详情、卡片和图片读取；页面依据服务端时钟自动移除便笺，聊天旧卡片不继续显示正文或操作按钮。
- 后台独立清理循环每 10 秒执行一次，不依赖打开留言板或提醒发送开关；读写和媒体入口也主动清理。服务端关闭期间不会运行任务，重启后立即执行首轮清理。
- 清理删除便笺记录及其已提交草稿副本，清除每日备份中的对应内容；图片仍被其他便笺或草稿引用时保留，最后一处引用到期后删除图片文件和元数据。原始聊天输入和聊天原附件继续由聊天自身管理。
- 幂等账本只保留请求指纹与资源 ID，不含正文与图片；到期后重试旧请求返回不可访问，不会重新发布。普通事项、日程与知识资料的保留规则不受影响。
- 新增验证覆盖三种可见来源自动合并、无人打开页面时后台清理、旧接口无法取回、图片及备份销毁、共享图片最后引用清理，以及旧草稿/旧请求不能恢复。便笺后端共 20 项通过。
