# 前端苹果风视觉改版需求文档

## 1. 背景

当前 React 前端已经具备完整的业务功能，包括登录、多会话聊天、流式响应、附件、分支树、会话共享、技能管理、系统配置、用户管理、Dashboard 和家庭事务页面。

现有视觉风格延续了早期原生前端的深色赛博风格，主要特征包括：

- 深黑背景、霓虹青主色、橙色辅助色；
- 扫描线、网格背景、发光边框和发光按钮；
- 大量等宽字体、全大写标签、协议流样式；
- 边框和阴影较重，界面区域分割偏硬；
- 聊天气泡、状态徽标、弹窗和侧栏带有明显 AI 工具模板感。

用户反馈当前前端“太像 AI 生成的界面”，但分支树显示相对好看。因此本次改版需要在保留现有功能和分支树可读性的基础上，将整体风格调整为接近 Apple 软件界面的简洁、克制、清晰和高级感。

## 2. 视觉 thesis

界面应像一个轻量、专注、安静的 macOS 生产力工具：浅色为主、深色可选，使用柔和材质、精确留白、稳定排版和克制动效，让用户把注意力放在对话、分支和操作结果上。

## 3. 总体目标

### 3.1 核心目标

- 将整体视觉从“赛博霓虹 AI 工具”调整为“苹果式简洁生产力应用”。
- 保留现有 React 前端功能，不改变 API 行为和业务流程。
- 建立统一设计 token，减少硬编码颜色、边框、阴影和字体。
- 让聊天页成为视觉重点：左侧会话清晰、中央对话舒适、右侧分支树精致。
- 保留分支树的结构优势，并将其材质、颜色和交互反馈融入新风格。
- 同时覆盖登录页、聊天页、Dashboard、家庭事务页、弹窗、表单、移动端。
- 支持系统浅色/深色模式，优先完成浅色模式，深色模式保持同等可读性。

### 3.2 体验目标

- 第一眼更像原生 macOS / iPadOS 应用，而不是网页模板。
- 信息密度适中，适合长时间对话和管理任务。
- 操作按钮清楚但不抢眼。
- 状态反馈准确、轻盈，不使用强烈发光或夸张动画。
- 移动端不拥挤，面板切换自然。

## 4. 非目标

本次视觉改版不包含：

- 不重写 React 架构；
- 不更改后端 API；
- 不新增复杂业务功能；
- 不把应用做成 Apple 官网式营销页面；
- 不引入大型 UI 框架导致现有组件大规模重写；
- 不为了“苹果风”复制 Apple 商标、图标、产品文案或品牌资产；
- 不牺牲分支树、工具调用、Markdown、附件、流式响应等现有功能可用性。

## 5. 设计原则

### 5.1 简洁

- 移除扫描线、霓虹网格、强发光、重渐变、科技感装饰。
- 使用真实布局层级表达结构，而不是用大量边框强调每个区域。
- 页面文案使用产品功能语言，避免口号式、营销式或提示词式表达。

### 5.2 克制

- 主色只保留一个系统蓝作为操作强调色。
- 状态色使用 Apple 语义色倾向：蓝、绿、橙、红、紫，但只在必要处出现。
- 动效时间短、曲线柔和，不出现跳动、闪烁、呼吸发光等强装饰动画。

### 5.3 清晰

- 字体优先使用系统字体：`-apple-system`, `BlinkMacSystemFont`, `SF Pro Text`, `Segoe UI`, `Noto Sans SC`, sans-serif。
- 等宽字体只用于代码、命令、token 统计、技术日志，不用于普通标签和按钮。
- 标题、正文、辅助信息、元数据需要形成明确字号层级。

### 5.4 材质

- 使用浅色磨砂、半透明层和极细描边建立 macOS 感。
- 毛玻璃只用于侧栏、顶部栏、浮层、弹窗等少数承载面。
- 主要阅读区域保持干净，不叠加复杂背景。

### 5.5 稳定

- 长文本、按钮、面板切换、流式内容不应导致明显布局抖动。
- 聊天输入框、消息区、侧栏和分支树面板需要有稳定尺寸约束。
- 移动端键盘弹出、侧栏打开、分支树打开时不应遮挡主要操作。

## 6. 设计 token 要求

### 6.1 颜色

需要建立新的语义 token，替代当前 `--neon`、`--neon-glow`、`--bg-0` 等赛博风变量。

建议浅色模式：

- `--app-bg`: `#f5f5f7`
- `--surface`: `rgba(255, 255, 255, 0.72)`
- `--surface-solid`: `#ffffff`
- `--surface-elevated`: `rgba(255, 255, 255, 0.86)`
- `--text-primary`: `#1d1d1f`
- `--text-secondary`: `#6e6e73`
- `--text-tertiary`: `#86868b`
- `--separator`: `rgba(0, 0, 0, 0.10)`
- `--separator-soft`: `rgba(0, 0, 0, 0.06)`
- `--accent`: `#007aff`
- `--success`: `#34c759`
- `--warning`: `#ff9500`
- `--danger`: `#ff3b30`
- `--purple`: `#af52de`

建议深色模式：

- `--app-bg`: `#0f0f10`
- `--surface`: `rgba(28, 28, 30, 0.72)`
- `--surface-solid`: `#1c1c1e`
- `--surface-elevated`: `rgba(44, 44, 46, 0.86)`
- `--text-primary`: `#f5f5f7`
- `--text-secondary`: `#a1a1a6`
- `--text-tertiary`: `#737377`
- `--separator`: `rgba(255, 255, 255, 0.12)`
- `--separator-soft`: `rgba(255, 255, 255, 0.08)`
- `--accent`: `#0a84ff`
- `--success`: `#30d158`
- `--warning`: `#ff9f0a`
- `--danger`: `#ff453a`
- `--purple`: `#bf5af2`

禁止项：

- 不再使用霓虹青作为全局主色；
- 不使用大面积黑青渐变；
- 不使用发光阴影作为默认状态；
- 不使用页面级扫描线和网格背景。

### 6.2 字体

- 全局字体使用系统无衬线字体栈。
- 中文界面需要保证 `Noto Sans SC` 或系统中文字体 fallback 正常。
- 等宽字体只用于代码块、命令、技术输出、token 数字等场景。
- 普通 UI 标签不使用全大写英文风格。

字号建议：

- 页面标题：28-34px；
- 区域标题：17-22px；
- 正文：14-15px；
- 辅助文本：12-13px；
- 表格和列表元数据：12px；
- 按钮：13-14px。

### 6.3 圆角

- 小控件：8px；
- 输入框和按钮：10-12px；
- 弹窗和浮层：14-18px；
- 聊天气泡：18-22px；
- 大面积卡片不超过 16px，避免“AI 卡片模板”感。

### 6.4 阴影

阴影应接近 macOS 浮层：

- 常规区域默认不使用阴影，只用背景和细分割线。
- 浮层、菜单、弹窗使用轻阴影。
- 禁止全局发光、彩色 glow 和厚重黑影。

### 6.5 间距

- 主工作区横向留白比当前更舒展。
- 列表项内部间距保持紧凑，适合扫描。
- 聊天气泡间距略增，提升长对话阅读体验。
- 面板边界不使用厚边框，通过背景层级和 separator 区分。

## 7. 页面级需求

### 7.1 聊天工作台

聊天工作台是本次改版核心。

布局要求：

- 保持左侧会话栏 + 中央聊天区 + 右侧分支树面板结构。
- 背景使用浅灰 `--app-bg`，中央聊天区使用干净阅读面。
- 顶部栏采用半透明磨砂效果，固定在主区域顶部。
- 侧栏宽度保持 260px 左右，但视觉上更像 macOS sidebar。
- 中央消息最大宽度可保持 820px，但需要更好的行宽和段落节奏。
- 输入区固定在底部，材质类似 macOS floating input bar，但不要过度悬浮。

顶部栏要求：

- 显示当前会话标题、状态、token 信息、分支树按钮。
- 状态徽标从霓虹胶囊改为轻量文本或浅色圆点。
- 忙碌状态使用柔和进度点或细进度条，不使用跳动发光点。
- 顶部栏按钮使用图标按钮，hover 背景轻微变化。

消息区要求：

- 用户消息使用系统蓝浅底或蓝色气泡，文字对比清晰。
- 助手消息使用白色/透明阅读块，弱化边框。
- final 消息不再使用霓虹渐变，改为轻微强调的摘要块。
- tool/protocol/process 消息使用折叠式或轻量日志样式，避免占用过多视觉注意。
- Markdown 代码块使用柔和灰底，不使用黑底霓虹边框。
- 链接使用系统蓝，hover 下划线即可。
- 表格使用细线和浅灰表头。
- 图片附件保持圆角和细描边。

输入区要求：

- 输入框更接近 Apple Messages / Notes 风格。
- 左侧附件按钮为低调图标按钮。
- 发送按钮使用系统蓝圆形或圆角方形图标按钮。
- focus 状态使用蓝色细描边或浅色 focus ring，不使用 glow。
- 附件 chip 使用浅灰胶囊，文件名不溢出。

### 7.2 左侧会话栏

目标是从“科幻控制台”改为“macOS sidebar”。

要求：

- 移除侧栏右侧霓虹发光线。
- 品牌区简化：保留产品名和用户状态，不使用强渐变 icon。
- 新建会话按钮改为清晰的 toolbar/button 样式，可使用 `Plus` 图标。
- 会话列表使用浅色选中态，类似 Finder / Notes 选中行。
- active 会话使用系统蓝浅底或蓝色文字，不使用左侧霓虹条。
- 时间和共享信息使用次级灰色。
- 更多菜单使用标准浮层菜单样式。
- session busy 状态使用小型进度圆点或 `Activity` 状态，不发光。

### 7.3 分支树面板

用户认为当前分支树显示相对好看，应保留其优点。

保留项：

- 保留树状结构、节点摘要、active path、节点点击、分支删除菜单；
- 保留适度的网格辅助线，因为它对图结构定位有帮助；
- 保留当前 SVG 自绘实现，不要求替换库。

调整项：

- 网格线颜色改为浅灰/深灰低透明度，不使用霓虹青；
- active path 使用系统蓝或紫色强调，避免发光；
- 节点卡片使用白色/深色 surface，描边更细；
- inactive 节点透明度保留，但 hover 过渡更柔和；
- 面板标题从 `// Branch Tree` 改为中文或产品化标题，如“分支树”；
- 关闭按钮、resize handle、toggle 按钮改为统一图标按钮样式；
- 分支树空状态使用普通提示，不使用等宽科技风。

### 7.4 登录页

要求：

- 背景使用柔和浅灰或系统渐变，不使用赛博黑底。
- 登录框居中但不过度卡片化，类似 macOS 设置面板。
- 输入框、按钮、错误提示沿用全局 token。
- 初始管理员提示要清楚，但不使用警告式强色块。

### 7.5 Dashboard

Dashboard 属于运营/监控页面，不应做成营销首页。

要求：

- 保持信息密度，减少卡片堆叠感。
- KPI 区使用紧凑 tile，但边框和阴影更轻。
- 图表颜色使用 Apple 语义色 palette。
- 表格、工具调用列表、热力图保持扫描效率。
- 搜索、筛选、刷新按钮风格统一。
- 图表背景不使用黑底，不使用霓虹路径。

### 7.6 家庭事务页面

要求：

- 当前页面偏 dashboard card 风，需要改为更生活化但仍克制的工具界面。
- KPI、冰箱清单、提醒、通知仍然保留。
- 表单区域更轻，不嵌套过多边框。
- 成功消息不使用 `pre` 的技术日志外观，改为轻量通知条。
- 图标颜色使用语义色，不全部使用主色。

### 7.7 弹窗和浮层

要求：

- 弹窗背景使用 `--surface-elevated` 和 backdrop blur。
- 标题栏简洁，关闭按钮使用标准 icon button。
- 表单 label 不使用全大写等宽字体。
- 主按钮使用系统蓝，次按钮使用灰色/透明。
- 危险操作使用红色文字或红色轻按钮。
- 菜单宽度、padding、hover 态统一。

## 8. 组件级需求

### 8.1 按钮

按钮类型：

- Primary：系统蓝背景，白色文字或图标；
- Secondary：浅灰背景，主文字；
- Tertiary/Icon：透明背景，hover 显示浅灰；
- Danger：红色文字或红色浅底；
- Disabled：透明度降低，但仍保持可读。

要求：

- 图标按钮优先使用 `lucide-react`；
- 按钮高度统一为 32px、36px、40px 三档；
- 避免按钮文字全大写；
- 不使用发光 hover；
- hover 和 active 只做轻微背景、缩放或透明度变化。

### 8.2 输入框

要求：

- 背景使用白色/深色 elevated surface；
- border 使用 `--separator`；
- focus 使用系统蓝 focus ring；
- placeholder 使用 `--text-tertiary`；
- textarea 高度变化不能挤压主要操作区。

### 8.3 徽标和状态

要求：

- 状态 badge 只用于必要状态；
- 使用灰底、蓝底、绿底、橙底、红底的低饱和版本；
- 移除等宽全大写和 letter spacing；
- loading 使用轻量 spinner、progress bar 或文本状态。

### 8.4 列表

要求：

- 列表项 hover 背景轻微变化；
- active 态使用系统蓝浅底；
- 列表项之间尽量不用完整边框，使用间距或 separator；
- 更多操作默认隐藏，hover 或 focus 时显示；
- 键盘 focus 可见。

### 8.5 Markdown 内容

要求：

- Markdown 排版接近 Apple Notes / 文档阅读体验；
- 段落间距清晰；
- 标题不过大；
- 代码块可横向滚动；
- 表格移动端可横向滚动；
- 引用块使用灰色左边线，不使用霓虹色。

## 9. 动效需求

动效 thesis：

- 动效只服务于状态切换、浮层出现、消息生成和面板切换；
- 所有动效应轻、短、稳定；
- 尊重 `prefers-reduced-motion`。

具体要求：

- 消息出现：opacity + translateY 4px，150-220ms；
- 侧栏移动端打开：slide + fade，180-240ms；
- 分支树面板打开：宽度/transform 平滑过渡，200-260ms；
- 菜单/弹窗：scale 0.98 到 1 + fade，120-180ms；
- 按钮 active：轻微 scale 0.98；
- loading：使用柔和 spinner 或细进度，不使用发光脉冲。

禁止项：

- 不使用扫描线动画；
- 不使用霓虹闪烁；
- 不使用大幅弹跳；
- 不使用持续吸引注意的装饰动画。

## 10. 响应式需求

### 10.1 桌面端

- 1280px 以上：左侧会话栏、中央聊天、右侧分支树可同时显示。
- 1024-1279px：分支树可作为右侧 overlay 或压缩面板。
- 顶部栏和输入区保持固定，消息区独立滚动。

### 10.2 平板端

- 会话栏可折叠；
- 分支树作为右侧抽屉；
- 主聊天区保持优先级最高；
- 输入区触控目标不低于 44px。

### 10.3 手机端

- 默认只显示聊天区；
- 会话列表通过左侧抽屉进入；
- 分支树通过全屏或底部 sheet 展示；
- 输入区需要适配软键盘和 safe area；
- 消息气泡最大宽度应更宽，减少换行碎片；
- 顶部栏按钮数量需要收敛到 2-3 个主要入口。

## 11. 可访问性需求

- 所有图标按钮必须有 `aria-label` 或可见文本。
- 弹窗打开后焦点进入弹窗，关闭后焦点回到触发按钮。
- 菜单支持键盘导航和 Escape 关闭。
- 色彩对比满足 WCAG AA。
- 不依赖颜色作为唯一状态表达。
- 支持 `prefers-reduced-motion`。
- 支持系统 `prefers-color-scheme`。
- hover 态需要有对应 focus-visible 态。

## 12. 技术实施要求

### 12.1 CSS 组织

当前 React 前端的样式统一位于 `web-react/src/styles/`。改版建议分阶段处理：

第一阶段：

- 新增或改造全局 token；
- 用新 token 覆盖旧变量；
- 先移除全局扫描线、网格和 glow；
- 尽量不改组件结构。

第二阶段：

- 重构 `web-react/src/styles/base.css`、`layout.css`、`sessions.css`、`messages.css`、`modals.css`、`tree.css`；
- 将通用按钮、输入框、浮层、badge、列表样式抽为稳定 class；
- 减少重复色值和重复边框样式。

第三阶段：

- 将仍然偏全局的 CSS 逐步收敛到 `web-react/src/styles/` 或组件局部样式内；
- 保留必要的 legacy class，但避免重新引入旧 `web` 目录依赖；
- 为主题切换、暗色模式和组件测试建立稳定入口。

### 12.2 组件结构

可优先抽象：

- `IconButton`
- `Button`
- `Badge`
- `TextField`
- `Textarea`
- `Surface`
- `Menu`
- `Toast`
- `EmptyState`

抽象原则：

- 只有当多个页面确实重复使用时才抽象；
- 不为了做设计系统而打断当前业务；
- 抽象后仍允许业务组件传入清晰的语义状态。

### 12.3 图标

- 沿用 `lucide-react`；
- 优先使用图标表达工具按钮；
- 不手写装饰 SVG；
- 图标尺寸统一为 16px、18px、20px 三档。

### 12.4 浏览器兼容

- 支持现代 Chrome、Edge、Safari；
- backdrop-filter 需要提供普通半透明 fallback；
- 移动端 Safari safe area 必须保持可用。

## 13. 分阶段实施计划

### 阶段 1：全局风格降噪

目标：

- 去掉明显 AI/赛博感；
- 建立苹果风基础 token；
- 让聊天页第一眼变干净。

范围：

- `web-react/src/styles/base.css`

## 14. 验收标准

### 14.1 视觉验收

- 首屏不再呈现黑底霓虹、扫描线、赛博网格。

- 分支创建、分支树打开、节点切换、分支删除正常；

## 16. 风格对照

当前需要避免：

- 黑底霓虹；
- 科幻网格；
- 扫描线；
- glow 按钮；
- 过多等宽字体；
- 全大写标签；
- 彩色渐变卡片；
- 过重阴影；
- 每个区域都加边框；
- 大量模板化 dashboard 卡片。

目标应该接近：

- macOS sidebar；
- Apple Notes 的阅读舒适度；
- Apple Messages 的输入和气泡克制感；
- Finder / Settings 的列表和表单秩序；
- Safari / Xcode 式的轻量 toolbar；
- 系统蓝作为唯一主要操作色。
