# 家庭 Agent 主界面布局替代方案

## 背景

当前主界面采用左侧历史会话和功能组件、中间大对话区、右侧可隐藏分支树的三栏结构。这种结构符合通用大模型聊天产品的惯例，但对家庭 Agent 来说存在明显问题：

- 产品重心被“聊天记录”占据，而不是家庭状态、物品、提醒和成员协作。
- 用户每次都要通过对话重新进入任务上下文，缺少稳定的家庭事务入口。
- 右侧分支树强化了模型会话逻辑，对非技术家庭成员不够直观。
- 历史会话按时间堆叠，难以回答“家里现在有什么事”“谁要做什么”“什么快过期”这类家庭问题。

本项目的家庭 Agent 应从“聊天工具”转为“家庭事务助理”。主界面不应让对话成为唯一中心，而应让家庭对象、时间、空间、成员和提醒成为一等公民。

## 设计依据

结合 `ui-ux-pro-max` 技能检索结果，适合本产品的方向是：

- `AI-Native UI`：保留自然语言、流式反馈、上下文卡片和最少界面负担。
- `Zero Interface`：在家庭场景中，用户更想直接说需求，复杂控件应按需出现。
- `Smart Home/IoT Dashboard`：家庭状态需要房间、物品、提醒、异常状态等实时入口。
- `Productivity Tool`：家庭任务有协作、归属、完成、延期和追踪需求。
- UX 重点：避免异步内容造成布局跳动；固定区域要处理遮挡和 z-index；文本内容要控制宽度；移动端避免 `100vh` 布局问题；保留可预测的返回路径。

因此，推荐的改版方向不是继续优化三栏聊天，而是拆分为“家庭驾驶舱 + 情境化对话 + 事务视图”的组合。

## 备选布局

### 1. 家庭驾驶舱 + 底部对话抽屉

主屏展示家庭今日状态，对话输入收纳在底部或右下角抽屉中。

布局结构：

- 顶部：家庭名、当前时间、全局搜索、语音/文本快捷输入。
- 主区：今日提醒、快过期物品、待办、异常状态、最近家庭活动。
- 侧区或下方：常用入口，如冰箱、药箱、购物清单、家庭成员、通知。
- 对话：默认是一条紧凑输入栏，需要时展开为完整对话抽屉。

优点：

- 第一眼回答“家里现在发生什么”。
- 对话仍然可用，但不会压过家庭状态。
- 适合桌面和移动端统一设计。

缺点：

- 需要把当前会话、家庭记忆、提醒系统做成摘要卡片。
- 如果摘要质量差，首页会显得空泛。

适用程度：最高。适合作为首版主界面。

### 2. 房间地图 / 家庭空间布局

以家庭空间为主导航，用户从“厨房、冰箱、客厅、药箱、阳台”等位置进入事务。

布局结构：

- 中心：家庭空间地图或房间网格。
- 每个空间：显示状态点，例如冰箱有 3 件快过期、药箱有 1 个补货提醒。
- 右侧：选中空间的详情面板。
- 底部：自然语言输入，可直接说“冰箱里还有什么”。

优点：

- 家庭成员容易理解，不需要理解会话树。
- 非常适合物品管理、智能家居、房间任务。
- 比通用 AI 聊天界面更有产品辨识度。

缺点：

- 空间建模需要配置成本。
- 对纯文本任务和复杂推理任务不如驾驶舱高效。

适用程度：高。适合作为“家庭物品/空间”一级页面，不建议单独承担所有主界面功能。

### 3. 家庭时间线

以时间为主轴，把提醒、物品变化、家庭成员操作、Agent 建议整合为可追溯流。

布局结构：

- 左侧或顶部：今天、本周、本月、全部。
- 中心：按时间排序的事件流。
- 每条事件：来源、对象、操作、状态和快捷动作。
- 右侧：事件详情、相关会话、相关文件、分支记录。

优点：

- 符合家庭事务“发生、提醒、完成、追溯”的逻辑。
- 可以自然承接审计日志、提醒记录、通知记录。
- 比历史会话更适合找原因和回看变化。

缺点：

- 不适合承载所有主动操作，需要配合快捷入口。
- 信息量大时要做好筛选和折叠。

适用程度：高。适合作为第二核心视图，替代传统“历史会话列表”的大部分价值。

### 4. 家庭任务看板

把家庭日常拆成 `待确认`、`待处理`、`已延期`、`已完成` 等列，按任务卡片推进。

布局结构：

- 顶部：成员筛选、优先级、日期、空间。
- 主区：Kanban 列或列表。
- 卡片：任务、归属成员、来源、截止时间、完成/延期/转交按钮。
- 侧边：选中任务的对话和执行记录。

优点：

- 适合多成员协作，比如购物、家务、药品补充、缴费。
- 操作明确，比在聊天里找待办更可靠。
- 容易接入通知和状态流转。

缺点：

- 对“随便问一句”的轻量场景偏重。
- 如果家庭任务很少，界面会显得过度组织化。

适用程度：中高。适合作为“任务/提醒”页面，不建议作为默认首页。

### 5. 对象中心布局

以家庭对象作为主角，例如冰箱、药箱、账单、成员、宠物、植物、设备等，每个对象都有自己的状态页。

布局结构：

- 左侧：对象类型过滤，例如物品、成员、空间、提醒、文件。
- 主区：对象列表和状态卡。
- 右侧：对象详情，包括记忆、提醒、变更记录、关联会话。
- 输入栏：围绕当前对象发问或修改。

优点：

- 很适合“长期记忆”产品，所有信息有归属。
- 能把会话产生的记忆落到稳定实体上。
- 后续做权限、审计和备份更清晰。

缺点：

- 初期对象建模复杂。
- 用户需要理解“对象”概念，最好用空间和常用名包装。

适用程度：高。适合作为底层信息架构，也是多个页面共享的详情模式。

### 6. 命令中心 + 情境卡片

弱化固定导航，主界面以全局命令框为中心，下面展示系统根据上下文推送的卡片。

布局结构：

- 中心：大输入框，支持文本、语音、文件、图片。
- 下方：建议卡片，如“记录冰箱物品”“创建提醒”“查看今天任务”。
- 顶部：轻量状态条。
- 结果：以卡片、表单、确认面板展示，不强制进入聊天流。

优点：

- 极简，适合移动端和家庭成员快速使用。
- 很符合 Agent 产品“说需求即可”的心智。
- 能减少复杂菜单带来的学习成本。

缺点：

- 对长期浏览和管理不够强。
- 如果推荐卡片不准，用户会迷失。

适用程度：中。适合作为移动端默认形态，桌面端可作为全局快捷入口。

### 7. 分支树改为“决策与记忆图谱”

保留右侧可隐藏面板，但不再显示纯会话分支，而是显示本次任务影响了哪些记忆、提醒、文件和家庭对象。

布局结构：

- 中间：当前任务或对话。
- 右侧图谱：用户消息、Agent 推理、修改对象、提醒、文件记录。
- 节点：支持展开来源、回滚、确认、标记错误。

优点：

- 保留现有分支能力，但转译成用户更关心的影响关系。
- 适合解释“为什么 Agent 记住了这个”。
- 对可追溯、本地文件存储和审计很有价值。

缺点：

- 不适合默认展开，容易增加认知负担。
- 图谱交互复杂，需要渐进披露。

适用程度：中高。建议作为高级面板，替代现有右侧分支树。

### 8. 家庭通知收件箱

把提醒、异常、确认请求和系统建议集中成一个可处理的收件箱。

布局结构：

- 左侧或顶部：未读、待确认、已完成、系统建议。
- 主区：通知列表。
- 详情：一键完成、延期、转交、编辑提醒、查看来源。
- 对话：针对某条通知继续追问。

优点：

- 适合主动通知和 Web Push 体验。
- 家庭成员回到页面时能快速处理遗留事项。
- 比聊天历史更接近日常使用。

缺点：

- 不能替代信息浏览和对象管理。
- 需要清晰的通知分级，否则容易变成噪音。

适用程度：中高。适合作为顶部入口或首页重要模块。

## 推荐结论

建议采用“家庭驾驶舱为底层主页面，对话界面作为上层工作层”的布局。原聊天主界面继续保留，但不再与家庭驾驶舱做完全平级的页面切换；它应从家庭驾驶舱中的对话入口、快捷输入或历史会话打开，并覆盖在家庭驾驶舱之上。

关键修正：

- 家庭驾驶舱信息量更大，适合查看家庭状态、提醒、物品和时间线，但不应承载所有深度对话细节。
- 当前聊天主界面仍然适合自由提问、长对话、调试、技能调用和分支探索，不能被删除或完全降级。
- 家庭驾驶舱是默认主界面；点击驾驶舱里的对话框、快捷输入、任务卡片或历史会话后，进入“对话覆盖层”。
- 对话覆盖层与家庭驾驶舱有明确层级关系：驾驶舱在底层，对话在上层；不是两个互相割裂的页面。
- 对话层左上角必须提供“退出/返回驾驶舱”按钮，点击后关闭对话层并回到家庭驾驶舱，保留驾驶舱原滚动位置和状态。
- 打开对话层时应保留当前会话、输入草稿、分支树状态和上下文；关闭时不应销毁会话。
- 历史会话不是主界面的第一层，但点击任意历史会话应打开对应的对话覆盖层。

推荐信息架构：

```text
主工作台
├── 底层：家庭驾驶舱
├── 上层：对话覆盖层
├── 当前会话状态共享
├── 全局输入草稿共享
└── 右侧详情/记忆影响面板按层级变化

底层：家庭驾驶舱
├── 今日概览：提醒、待办、快过期、异常、未读通知
├── 对话入口：文本、语音、图片、文件
├── 常用对象：冰箱、药箱、购物清单、账单、家庭成员
├── 最近活动：家庭时间线摘要
└── 最近会话：点击后打开上层对话

上层：对话覆盖层
├── 左上角退出按钮：关闭对话层，返回家庭驾驶舱
├── 原消息列表
├── 原输入框
├── 当前会话标题和状态
└── 原分支树能力

空间与物品
├── 厨房 / 冰箱 / 食品柜 / 药箱
├── 对象详情
└── 变更记录与关联提醒

任务与提醒
├── 待确认
├── 待处理
├── 已延期
└── 已完成

家庭时间线
├── 今天
├── 本周
├── 全部
└── 筛选：成员 / 空间 / 对象 / 来源

对话与执行
├── 对话覆盖层
├── 上下文卡片
└── 决策与记忆图谱
```

首版落地优先级：

1. 保留当前聊天主界面，不删除现有消息列表、输入框、历史会话和分支树。
2. 将家庭驾驶舱设为底层主页面，展示“今日状态 + 对话入口 + 情境卡片”。
3. 点击驾驶舱中的对话框、快捷建议、任务卡片或历史会话时，在驾驶舱上方打开对话覆盖层。
4. 对话覆盖层复用当前聊天主界面能力：消息列表、输入框、技能调用、分支树。
5. 对话覆盖层左上角必须有退出按钮，点击后返回家庭驾驶舱，而不是跳转到另一个页面。
6. 左侧栏改为家庭导航优先，但要保留“最近对话”入口；点击最近对话打开上层对话层。
7. 右侧分支树在对话层继续按原能力使用；在驾驶舱底层只在需要时作为“详情/记忆影响”面板出现。
8. 历史会话不要从第一阶段移除，只从“唯一主导航”降级为“最近对话/搜索/对象关联会话”。

## 推荐移动端布局

移动端不建议沿用三栏折叠。应采用“家庭驾驶舱底层 + 全屏对话覆盖层”的结构：

- 底部导航：首页、空间、任务、时间线、我的。
- 首页顶部：家庭状态摘要和语音/文本输入。
- 点击输入、快捷建议、任务卡片或历史会话后，打开全屏对话覆盖层。
- 对话覆盖层左上角固定显示退出按钮，点击后关闭覆盖层并回到家庭驾驶舱。
- 系统返回手势或浏览器返回键应优先关闭对话覆盖层，而不是直接离开应用。
- 对象详情、任务详情、通知详情都使用独立页面，保留系统返回路径。
- 不使用 `100vh` 固定高度，优先使用 `min-h-dvh` 并处理输入法遮挡。

## 视觉方向

建议避免企业后台感和纯聊天感，采用克制的家庭生产力风格：

- 背景：浅色为主，使用暖白或低饱和中性色，不以深色仪表盘为默认。
- 状态色：绿色表示正常/完成，琥珀表示临期/待确认，红色表示过期/失败，蓝色表示信息。
- 图标：统一使用 Lucide 或同一套 SVG 图标，不使用 emoji 作为功能图标。
- 卡片：只用于具体对象、任务和通知，不把整页区域做成多层卡片。
- 动效：只用于状态变化、抽屉展开、流式反馈，尊重 `prefers-reduced-motion`。
- 信息密度：首页要可扫读，详情页再承载完整字段。

## 反模式

需要避免的改版方向：

- 继续把会话历史作为左侧主导航，把家庭功能塞成普通侧边栏按钮。
- 直接删除或隐藏原聊天主界面，强迫所有用户进入复杂家庭驾驶舱。
- 把家庭驾驶舱和聊天主界面做成完全平级页面，导致用户在家庭状态和对话之间来回跳转、丢失主页面上下文。
- 对话覆盖层没有明确退出按钮，只能依赖浏览器返回或侧栏导航。
- 首页只有一个大聊天框和一些提示词卡片，缺少真实家庭状态。
- 右侧持续显示复杂分支树，让普通家庭成员承担模型工作流的认知成本。
- 所有家庭数据都只能从聊天记录里找，缺少对象详情页和时间线。
- 大量使用悬浮面板、嵌套卡片、透明玻璃效果，导致家庭事务信息不易读。
- 只做桌面三栏适配移动端，导致小屏幕上导航、输入和详情互相遮挡。

## 最终建议

最合适的方向是：

> 家庭驾驶舱是主页面和底层上下文；聊天主界面是从驾驶舱上方打开的对话覆盖层。用户点击驾驶舱中的对话框、快捷入口或历史会话后进入对话层；对话层左上角提供退出按钮，点击后返回家庭驾驶舱。

这样既保留 Agent 的自然语言优势和原有聊天效率，又能建立家庭产品自己的信息架构。用户在处理家庭事务时始终以驾驶舱为锚点，需要深入对话时进入上层工作区，结束后自然回到家庭当前状态，而不是在两个平级页面之间跳转。
