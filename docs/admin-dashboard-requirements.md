# 后台数据看板需求文档

## 1. 背景与目标

当前服务是一个 FastAPI Web UI + 多会话 Agent 系统，已经具备会话持久化、分支对话、流式输出、技能系统、token 估算和基础诊断接口。

本次新增后台看板，用于集中观察系统使用情况、模型上下文消耗、各会话行为、工具调用情况和内容主题分布，帮助快速判断：

- 当前服务是否被高频使用；
- 哪些会话消耗 token 最多；
- 哪些工具/命令调用最频繁、失败率最高；
- 对话主题集中在哪里；
- 上下文压缩、分支、技能注入是否带来明显 token 成本；
- 是否存在异常会话、异常工具输出或高成本请求。

## 2. 设计定位

看板是后台运维与使用分析界面，不做营销页，不使用夸张装饰。视觉方向采用苹果风格：

- 浅色优先，支持深色模式；
- 大面积留白、柔和玻璃质感、细边线、低饱和色；
- 信息密度高但层级清晰；
- 圆角控制在克制范围内，图表和表格优先；
- 动效用于状态变化和数据过渡，不做干扰性动画。

视觉主题建议：

- 背景：`#f5f5f7` / 深色 `#0b0c0f`;
- 主文字：`#1d1d1f`;
- 辅助文字：`#6e6e73`;
- 主强调色：系统蓝 `#007aff`;
- 风险色：系统红 `#ff3b30`;
- 成功色：系统绿 `#34c759`;
- 警告色：系统橙 `#ff9500`。

## 3. 使用入口

建议新增独立后台入口：

- 前端路由：`/dashboard` 或 `/admin`;
- API 前缀：`/api/dashboard/*`;
- 现有聊天页面保留不变，在侧边栏或顶部增加“后台看板”入口。

首版可不引入前端构建工具，继续沿用当前 `web/index.html` + `web/js/*.js` 的原生模块模式；图表可使用轻量可视化库，或先用 SVG/Canvas 实现核心动态图表。

## 4. 数据来源现状

当前已有数据：

- `ConversationStore` 会持久化 `.data/conversations/*.json`;
- 每个 session 已有 `token_usage`;
- 每条消息已自动标注 `usage`;
- `/api/token-usage` 已返回系统提示词、技能 token、会话 token 汇总；
- 流式聊天事件中已有 `model_start`、`model_done`、`command_start`、`command_result`;
- 工具调用可通过消息内容 `[命令]`、`[执行完成]` 和 `usage.category` 推断。

首版可直接基于会话 JSON 和现有 token 估算聚合数据。

需要新增或加强的数据：

- 工具调用次数、成功率、失败率、耗时；
- 模型调用耗时、轮次、上下文消息数；
- 每次请求的输入 token、输出 token、工具 token 分布；
- 会话活跃时间线；
- 词云需要对用户消息、助手消息或命令文本做分词与停用词过滤；
- 若要真实 token 成本，需要保存模型 API 返回的真实 usage 字段；当前是近似估算。

## 5. 核心页面结构

### 5.1 总览页

显示系统全局状态和核心 KPI：

- 总会话数；
- 总消息数；
- 总 token 数；
- 今日/近 7 天/近 30 天 token 数；
- 总工具调用数量；
- 工具调用成功率；
- 活跃会话数；
- 平均每会话 token；
- 平均每次模型调用消息数；
- 最大 token 会话；
- 最近更新时间。

可视化组件：

- KPI 数字卡，数字使用平滑递增动画；
- token 趋势折线图；
- 工具调用堆叠柱状图；
- 用户/助手/工具 token 环形图；
- 最近活跃会话列表；
- 异常提示条，例如“高失败率工具”“超长会话”“高 token 峰值”。

### 5.2 Token 使用分析

分析 token 成本结构：

- 系统提示词 token；
- 技能文件 token；
- 会话历史 token；
- 用户 token；
- 助手 token；
- 工具调用 token；
- 工具结果 token；
- 摘要 token；
- 分支路径上下文 token。

可视化组件：

- 全局 token 构成瀑布图；
- 按会话排序的 token 横向柱状图；
- token 随时间变化的面积图；
- 用户/助手/工具 token 分层面积图；
- 单会话 cumulative token 曲线；
- token Top N 会话表格；
- 技能 token 占比图。

建议指标口径：

- `total_tokens`：会话总估算 token；
- `conversation_tokens`：非系统提示和技能的普通对话 token；
- `tool_tokens`：工具调用与工具结果 token；
- `summary_tokens`：压缩摘要 token；
- `skill_tokens`：技能上下文 token。

### 5.3 会话使用情况

按会话维度观察使用情况：

- 会话标题；
- 创建时间；
- 最近更新时间；
- 消息数量；
- 分支节点数量；
- 活跃分支深度；
- token 总量；
- 工具调用次数；
- 工具失败次数；
- 平均回复轮次；
- 最近一次模型调用耗时；
- 是否发生上下文压缩。

可视化组件：

- 会话排行榜；
- 会话活跃热力图；
- token 与消息数散点图；
- 分支复杂度树图；
- 会话生命周期时间线；
- 会话详情抽屉。

会话详情建议展示：

- token 构成；
- 消息角色分布；
- 工具调用明细；
- 分支树摘要；
- 关键词词云；
- 最近消息预览；
- 异常事件。

### 5.4 工具调用分析

当前服务中的工具调用主要来自模型输出的 `[命令]`，并由 `CommandExecutor` 执行。

需要展示：

- 总工具调用数量；
- 成功/失败数量；
- 成功率；
- 平均输出长度；
- 平均耗时；
- Top 命令；
- Top 失败命令；
- 按会话统计的工具调用次数；
- 按时间统计的工具调用趋势；
- 危险命令拦截次数；
- 连续失败中止次数。

可视化组件：

- 工具调用总量趋势柱状图；
- 成功/失败堆叠图；
- 命令 Top N 横向柱状图；
- 工具调用 Sankey 流向图：会话 -> 命令类型 -> 成功/失败；
- 工具失败原因列表；
- 最近工具调用实时流。

命令分类建议：

- `shell_read`：`ls`、`cat`、`sed`、`rg` 等读取类；
- `shell_write`：写文件、格式化、生成文件；
- `test`：`pytest`、`npm test`、`xcodebuild test` 等；
- `server`：启动服务；
- `network`：`curl`、下载、API 请求；
- `git`：git 操作；
- `blocked`：被安全策略拒绝；
- `unknown`：无法归类。

### 5.5 词云与主题分析

词云用于观察用户问题、助手回复、工具命令和技能使用的主题分布。

展示范围：

- 全部会话词云；
- 单会话词云；
- 用户消息词云；
- 助手消息词云；
- 工具命令词云；
- 技能名/技能内容词云。

处理规则：

- 过滤系统提示词；
- 过滤常见停用词；
- 过滤过短词；
- 中文建议使用简单 n-gram 或可选分词库；
- 英文按 token/word 切分；
- 命令词云单独计算，避免 `python`、`echo` 等高频词淹没主题；
- 支持点击词语筛选相关会话。

可视化组件：

- 动态词云图；
- 关键词趋势线；
- 主题 Top N 条形图；
- 关键词与会话关联矩阵。

## 6. 额外建议的可视化内容

### 6.1 成本雷达图

对单个会话展示五个维度：

- token 消耗；
- 工具调用密度；
- 分支复杂度；
- 上下文压缩程度；
- 最近活跃度。

用途：快速识别“成本高但价值低”或“工具调用异常密集”的会话。

### 6.2 会话分支复杂度图

基于现有分支树数据，展示：

- 分支数量；
- 最大深度；
- 活跃路径长度；
- 被压缩节点数量；
- 分支切换次数。

可做成可缩放树图或紧凑迷你树。

### 6.3 Token 预算仪表盘

展示当前模型上下文预算：

- 估算上下文上限；
- 当前最大会话 token；
- 触发压缩阈值；
- 摘要占比；
- 最近 10 次高 token 请求。

用途：提前发现上下文膨胀。

### 6.4 模型调用漏斗

展示一次请求的完整路径：

用户输入 -> 技能注入 -> 上下文构建 -> 模型输出 -> 工具调用 -> 工具结果 -> 最终完成。

指标：

- 每个阶段耗时；
- 每个阶段 token 变化；
- 是否触发重试；
- 是否触发命令失败中止。

### 6.5 请求时段热力图

按小时和日期展示使用高峰：

- 横轴：小时；
- 纵轴：日期；
- 颜色：消息数、token 数或工具调用数。

### 6.6 异常监控面板

展示需要关注的异常：

- 单会话 token 过高；
- 工具连续失败；
- 被拒绝执行的危险命令；
- 输出过长；
- 模型回复格式错误重试；
- 会话文件损坏或读取失败；
- API 请求错误。

### 6.7 技能使用分析

统计技能系统使用情况：

- 技能总数；
- 每个技能文件 token；
- 被激活次数；
- 激活技能后的平均 token 增量；
- 技能相关会话；
- 长期未使用技能。

### 6.8 内容长度分布

展示消息内容长度和输出长度：

- 用户输入长度分布；
- 助手回复长度分布；
- 工具输出长度分布；
- 长输出 Top N。

### 6.9 会话健康评分

给每个会话生成 0-100 的健康分：

- token 越接近压缩阈值扣分；
- 工具失败率越高扣分；
- 重试越多扣分；
- 分支过复杂扣分；
- 长时间未更新不扣分，但标记为归档候选。

## 7. 数据 API 需求

建议新增以下接口。

### 7.1 获取看板总览

`GET /api/dashboard/summary`

返回：

- 全局 KPI；
- token 总览；
- 工具调用总览；
- 近期趋势；
- 异常摘要。

### 7.2 获取会话分析列表

`GET /api/dashboard/sessions?range=30d&sort=total_tokens&limit=50`

返回：

- 会话基础信息；
- token 使用；
- 消息数量；
- 工具调用数量；
- 分支指标；
- 活跃时间。

### 7.3 获取单会话分析

`GET /api/dashboard/sessions/{session_id}`

返回：

- 单会话 KPI；
- token 曲线；
- 消息角色分布；
- 工具调用明细；
- 词云数据；
- 分支复杂度；
- 异常事件。

### 7.4 获取工具调用分析

`GET /api/dashboard/tools?range=30d`

返回：

- 总调用量；
- 成功率；
- 命令分类；
- Top 命令；
- 失败原因；
- 时间序列。

### 7.5 获取词云数据

`GET /api/dashboard/word-cloud?scope=user&session_id=optional&limit=120`

返回：

- word；
- weight；
- scope；
- related_session_count。

### 7.6 获取趋势数据

`GET /api/dashboard/timeseries?metric=tokens&bucket=day&range=30d`

支持指标：

- `tokens`;
- `messages`;
- `tool_calls`;
- `tool_failures`;
- `sessions`;
- `model_calls`;
- `avg_latency`。

## 8. 数据模型补充

为了让工具调用和模型调用统计更准确，建议在会话 JSON 中新增 `events` 字段，保存结构化事件。

示例：

```json
{
  "events": [
    {
      "id": "event_id",
      "type": "model_call",
      "session_id": "session_id",
      "iteration": 1,
      "model": "qwen-plus",
      "message_count": 12,
      "started_at": "2026-05-25T09:00:00Z",
      "finished_at": "2026-05-25T09:00:03Z",
      "duration_ms": 3000,
      "estimated_input_tokens": 1200,
      "estimated_output_tokens": 300
    },
    {
      "id": "event_id",
      "type": "tool_call",
      "session_id": "session_id",
      "iteration": 1,
      "tool": "shell",
      "command": "rg token_usage -n",
      "category": "shell_read",
      "success": true,
      "return_code": 0,
      "started_at": "2026-05-25T09:00:04Z",
      "finished_at": "2026-05-25T09:00:04Z",
      "duration_ms": 180,
      "output_chars": 3200
    }
  ]
}
```

首版兼容策略：

- 如果没有 `events`，从 `messages` 推断；
- 新请求写入 `events`;
- 旧会话无需迁移即可展示基础统计；
- 提供可选刷新接口补齐派生指标。

## 9. 前端交互需求

### 9.1 筛选

支持：

- 时间范围：今天、7 天、30 天、全部；
- 会话；
- 模型；
- 工具分类；
- 成功/失败；
- token 区间；
- 关键词搜索。

### 9.2 动态图表

要求：

- 首次进入有轻量入场动画；
- 数字 KPI 平滑变化；
- 折线/柱状图切换筛选时有过渡；
- 鼠标悬停展示 tooltip；
- 点击图表元素可联动筛选；
- 图表空数据时展示简洁空状态；
- 移动端降级为纵向布局。

### 9.3 表格

支持：

- 排序；
- 搜索；
- 分页或虚拟滚动；
- 点击进入详情；
- 高 token、高失败率、高复杂度用状态色标记。

## 10. 权限与安全

后台看板会展示命令、路径、工具输出摘要等敏感信息，建议：

- 默认仅本地访问；
- 如果未来对外开放，必须加认证；
- API KEY 不得展示；
- 工具输出只展示摘要，详情需要展开；
- 命令中的敏感参数需要脱敏；
- 支持隐藏系统提示词内容，只展示 token 数。

## 11. 性能要求

- 总览接口目标响应时间小于 500ms；
- 会话数量较多时避免每次前端全量拉取完整消息；
- 后端聚合时只读取必要字段；
- 可增加内存缓存，按会话 `updated_at` 失效；
- 词云计算可以缓存；
- 大会话详情按需加载；
- 前端图表在 1000 个点以内直接渲染，超过后端聚合降采样。

## 12. 验收标准

首版完成后应满足：

- 有后台看板入口；
- 能看到全局 token、会话数、消息数、工具调用总数；
- 能看到各会话 token 与工具调用情况；
- 能看到工具调用成功/失败统计；
- 能看到词云图；
- 至少包含 4 类动态图表；
- 能进入单会话详情；
- 旧会话数据可展示基础指标；
- 新会话可记录更完整的模型调用和工具调用事件；
- 页面在桌面端和移动端均可使用；
- 不影响现有聊天、分支和技能功能。

## 15. 待确认事项

- 后台是否需要登录权限；
- token 是否必须使用模型真实 usage，还是接受当前估算；
- 工具调用是否只统计 shell 命令，还是未来会扩展到浏览器、文件、插件等工具；
- 是否需要成本换算，例如按模型单价估算人民币/美元成本；
- 看板是否要实时刷新；
- 是否需要导出报表；
- 是否需要为旧会话做一次性数据迁移。
