# 按任务加载工具

CLI 和 Web 聊天共用同一套按需加载流程。工具仍由注册表保存，注册不等于把全部参数定义发送给模型。管理接口的工具清单保留完整列表，便于检查系统能力；它不是每次模型请求的工具列表。

## 请求流程

1. 新任务默认仅发送 `tool_load` 和已注册的 `skill_load`，同时提供按权限过滤的简短工具类别目录。普通问答及直接看图可以直接回答。
2. 模型需要行动时调用 `tool_load`，通过任务描述 `query` 搜索、`group` 限定类别，或用 `names` 加载已知工具名。查询支持中英文词项及中文二元词组匹配，不依赖额外模型请求，也不是语义检索；不匹配时应换词、指定类别或名称。
3. 加载器返回全部匹配工具的名称和简短说明。完整参数定义只在下一轮请求的 `tools` 中提供，避免在工具返回正文中重复放置 Schema。
4. 模型按完整参数定义调用具体工具，仍通过原有参数校验、业务权限、审批、执行和结果回传链路。

例如，查询网页时先调用：

```json
{"query": "获取网页内容", "group": "public_web"}
```

下一轮出现 `http_request` 的参数定义后，再调用该工具。加载器只改变本任务可见的工具定义，不发起 HTTP 请求或执行写操作。

## 加载范围与生命周期

- 每次查询加载全部匹配工具，不设置匹配数量上限。类别查询同样返回该类别内的全部可用工具。
- `names` 可一次指定所需的任意数量工具，支持注册表别名。不可用或不被当前 Skill 允许的名称会拒绝，整批校验成功后才更新加载状态。
- 已加载工具在本任务内保留，不按数量自动淘汰。新任务清空上一任务的加载状态，继续按需加载。
- Skill 加载时预加载全部可用且获准的 `required_tools`；其余工具仍按需加载，并继续受 `allowed_tools` 限制。切换 Skill 时立即过滤不再允许的工具。
- 兼容旧调用中的 `offset`，返回该位置起的全部剩余匹配项，不再强制分页；`next_offset` 恒为 `null`。
- 模型从历史中已知某个工具名而直接调用时，会在参数和 Skill 权限校验后单独按需加载该工具，再沿原有审批与执行流程处理。工具加载是上下文管理，不是授权机制。
- 每个编排器持有自己的加载状态和控制工具，不向共享注册表写入请求级处理器，避免并发账号或会话串用状态。
- `loaded_tools` 写入 Run checkpoint，审批恢复和中断续跑从该状态恢复，并过滤当前已经移除或不再允许的工具。

## 日志与成本

模型请求开始事件记录 `tool_names`、`tool_count` 和 `tool_schema_chars`，便于核实实际发送的工具定义。模型 SDK 请求仍记录最终模型、图片数和转换错误。

2026-10-29 首次实现时，使用本项目 35 个业务工具的注册清单测量，完整工具定义为 16689 字符，首轮两个入口为 977 字符。以 `cl100k_base` 估算分别为 5597 和 323 tokens，类别目录另约 165 tokens。这是取消数量限制前的历史测量，入口定义文本此后有变化；不能作为当前版本的精确开销。这些也只是定义与目录的本地估算，不是供应商计费数据或整轮请求消耗。按需发现通常会增加一轮模型交互，后续加载的定义及工具结果也占用上下文。

## 验证

- `test/agent_runtime/test_tool_loading.py` 覆盖大注册表首轮按需加载、任务搜索、别名、匹配及显式加载超过 8 个、无自动淘汰、任务隔离、权限拒绝、Skill 所需工具不截断、流式/非流式执行和审批恢复。
- `test/test_media_api.py` 检查最终 SDK 请求中，直接识图不携带业务工具全集。
- 家庭事项、资料、留言板和 MCP 的集成回归保留业务权限、持久化及卡片检查。
- 首次实现的相关后端回归合计 175 项通过。取消数量限制后，针对加载器、原生运行循环、Web 媒体请求、MCP 及家庭工具的回归 65 项通过，明确验证了查询和显式加载 12 个工具、任务内不自动淘汰、超过 8 个工具的审批恢复，以及 Skill 所需工具不截断。`git diff --check` 通过。
- 真实 `qwen3.8-27b` 在隔离 Run 中完成了 `tool_load → datetime_now → 回答`。测试只开放实际读取时间，其他处理器被替换为拒绝执行，不写入真实业务数据；该真实测试的注册表包含 5 个基础工具。35 项清单的开销测量单独执行，没有把它宣称为 35 项业务工具的真实任务评测。

核心实现见 [tool_loading.py](../agent_runtime/tool_loading.py) 和 [orchestrator.py](../core/orchestrator.py)。运行中的后端需重启加载新代码。
