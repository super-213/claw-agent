# 家庭接龙与家庭投票实施计划

日期：2026 年 10 月 30 日  
状态：P0—P3 已实现，P4 自动化／浏览器与真实模型验收完成；真实设备推送及 iPhone 真机待验收，尚未部署  
范围：工作台工具入口、家庭接龙、家庭投票、留言板交互、两类截止时间、创建者通知、自动销毁，以及 Agent 原生工具与交互卡片。

## 1 目标与现有实现

在工作台「写便笺」左侧增加「工具」按钮，点击后展示「新建家庭接龙」「新建家庭投票」。创建成功后，活动展示在家庭留言板，家人可以直接参与；创建者可以管理活动。Agent 可以创建、修改、查看、删除活动，并返回与留言板绑定同一真实对象的交互卡片。

产品交互参照群接龙、群投票的常见形式：接龙按序展示成员提交内容，投票展示题目、选项、本人选择与统计。本计划不以微信当前版本的具体能力作为实现依据，也不追求逐项复刻。

## 2 创建入口与留言板体验

### 2.1 工具菜单与创建表单

工具栏顺序为「工具」「写便笺」，保持现有小组件／留言板切换。工具菜单支持点击、键盘、Esc、点击外部关闭和关闭后焦点恢复；手机使用适合触控的菜单或底部弹层。

选中类型后打开对应表单，复用 `HomeDialog` 和卡片字段组件：

| 通用字段 | 规则 |
| --- | --- |
| 标题、说明 | 标题必填；说明可选，首版文字即可 |
| 参与截止 | 「不设截止」或带时间的具体截止，明确显示家庭时区 |
| 存在截止 | 「长期保留」或具体销毁时间，提示到点删除活动与参与数据 |
| 完成规则 | 默认全员完成后结束；可以关闭自动结束，接龙可另设名额 |
| 创建者通知 | 默认开启「到参与截止／提前完成时通知我」，可关闭 |
| 发布范围 | 清楚展示「发布到家庭留言板，家庭成员可参与」，首版不增加私人活动与指定成员共享 |

两类时间独立配置，不强制都设置，也不偷偷补默认截止时间。两者都设置时要求 `参与截止时间 <= 存在截止时间`，均必须晚于成功发布时刻；相等合法，但界面提示「截止即销毁，结束后无法查看结果」。相对时长以发布成功时刻起算，草稿反复保存不开始计时。

表单底部提供「发布家庭接龙／发布家庭投票」「取消」。关闭后可继续本人未过期草稿；草稿不展示在留言板。发布中防重复提交，超时显示结果待核实并沿用同一请求 ID，不盲目重建。

### 2.2 留言板呈现

- 活动与便笺混合展示，每项使用有类型的稳定 ID；活动显示类型、标题、创建者、参与进度、当前状态与两类截止时间。
- 桌面保持固定大小的摘要卡和独立拖动区域，卡内按钮、选项及滚动不触发拖动；手机沿用双列摘要，进入详情后完成完整参与流程。
- 投票摘要显示本人是否投过及票数摘要；接龙摘要显示最近条目、已接龙人数和剩余名额。列表不塞入完整长表单。
- 详情和聊天使用相同的 `InteractiveCardHost` 及业务适配器。本人投票、改票、加入、修改条目等按钮调用认证 API，不再请求模型。
- 结束后至销毁前保留结果和结束原因，只读；到存在截止时自动移除。空状态、加载失败和「查看更多」文案由便笺扩展为留言板内容。
- 新活动获得初始位置，不重排旧便笺；保留原便笺 ID 的布局键。新类型使用命名空间键，避免 ID 冲突和重置已有摆放。

## 3 家庭投票规则

| 项目 | 首版行为 |
| --- | --- |
| 基础内容 | 一个题目、可选说明、至少两个非空且可区分的选项；选项使用稳定 ID |
| 选择模式 | 单选／多选；多选明确最少和最多选择数 |
| 本人选票 | 一人一份有效选票，重复提交更新本人选票，不累计虚假票数 |
| 改票与撤票 | 由创建者发布前配置是否允许，默认允许；仅活动进行中可用 |
| 结果展示 | 首版实名，家人可看统计及参与名单；界面明确提示实名，不提供未实现的匿名开关 |
| 统计 | 显示参与人数、每项得票数和占参与人数比例；多选比例之和可以超过 100%，清楚标注口径 |
| 全员完成 | 自动结束开启时，完成判定成员均已有有效选票，即提前结束并冻结最终结果 |
| 管理 | 创建者可在规则允许范围修改、主动结束或删除，不能替其他成员投票、改票 |

已有人投票后，题目、选项内容、选项集合、单多选与改票规则等影响投票含义的配置冻结，避免原选票被改作另一问题；说明和截止时间可在进行中修改。发现题目需要实质调整时提示结束后重新创建，不清票重开同一活动。截止后的活动不能通过改时间重新开放。

首版不含匿名投票、多题问卷、加权投票和跨家庭投票；后续扩展仍遵守实名／匿名数据边界。

## 4 家庭接龙规则

| 项目 | 首版行为 |
| --- | --- |
| 基础内容 | 标题、说明、可选填写示例；默认一个文本内容字段 |
| 接龙内容 | 支持创建者配置少量文本、数字字段及必填项，服务端限制长度并校验类型；不提供任意表单脚本 |
| 本人条目 | 每名成员一条有效条目，可写人数、物品、数量等；本人身份由登录账号确定 |
| 序号 | 以成功加入顺序分配稳定序号，修改不换序号，撤回不重排既有序号；重新加入分配新序号 |
| 修改／撤回 | 进行中可修改或撤回本人条目；结束后只读 |
| 名额 | 可选参与成员名额上限，首版按有效条目数计数，表单中的「人数」不自动占多个名额 |
| 全部完成 | 全员均有有效条目，或达到配置名额，即按规则提前结束 |
| 管理 | 创建者可修改允许的活动配置、主动结束和删除，不能改写他人条目 |

已有参与后冻结字段定义与名额计数口径；名额只能调整到不低于当前有效条目数，调整后若达上限则立即结束。首版不提供代他人报名、同一成员多条接龙和支付收款。接龙内容使用普通文本展示，不执行 HTML。

## 5 两类时间与完成判定

### 5.1 状态和边界

活动状态为 `draft → open → closed → destroyed`，也允许从 `open` 或 `draft` 直接销毁。销毁后只留下必要的无正文防重放标识，不作为可浏览历史状态。`closed` 带 `close_reason=deadline/all_completed/capacity/manual`、`closed_at`；状态不可逆。

| 事件 | 业务动作 | 留言板／聊天 | 通知 |
| --- | --- | --- | --- |
| `now >= participation_deadline_at` | 结束参与，冻结选票／条目 | 保留结果，只读 | 开启通知时通知创建者一次 |
| 全员完成／接龙满额 | 提前结束，冻结结果 | 显示完成原因 | 开启通知时通知创建者一次 |
| 创建者主动结束 | 结束并冻结 | 显示主动结束 | 以操作回执为主，不额外重复推送 |
| `now >= expires_at` | 销毁活动、发布记录及参与数据 | 所有位置不可读，旧链接失效 | 取消未送达内容通知，不发送参与详情 |
| 创建者删除 | 立即销毁，复用相同清理流程 | 所有位置移除 | 不将删除当作活动完成 |

存在截止先于其他处理的访问优先级最高：截止边界一到，即使清理线程尚未运行，也不能读取内容或继续投票／报名。两截止相同时，事务内识别参与截止，但不创建包含已销毁结果的通知；可保留一次「家庭活动已结束并销毁」的通用提醒，不含标题、选项、条目和结果。

只有存在截止而没有参与截止时，活动可参与到销毁前；只有参与截止时，结束结果长期保留；均未设置时，依靠全部完成或主动结束。通知与自动结束是不同配置，关闭通知不改变业务结束规则。

### 5.2 「全部完成」的明确口径

建议首版默认：发布时快照当前家庭全部有效成员，包含创建者，作为 `completion_member_ids`；创建者需参与才能满足默认全员完成。发布页明确显示「共 N 人，包含你」，并允许关闭全员自动结束，避免创建者只负责发起时误以为其他人都参与就会自动结束。

- 新加入家庭的成员可查看、参与进行中的活动，但不自动扩大完成分母；不能让即将完成的活动因新成员加入无限延期。
- 已退出或停用的快照成员不再有访问权，生命周期核实成员状态后从有效完成分母剔除并记录成员变更原因；已有参与数据在活动销毁前按业务留存，不伪造其参与状态。
- 有效分母为空时不判为「全员已完成」，依靠截止或手动结束；分母变化导致满足完成条件时允许结束，并在结束原因中记录该变化。
- 全员判断、名额判断、本人提交和状态转换在同一事务内完成。若名额小于全员数，先达名额即可结束；条件同时满足使用固定原因优先级，通知仅一次。
- 到期与最后一人提交竞争时，以事务中服务端时间判断：到参与截止即拒绝新参与。最后一份合法提交触发提前结束后，不再允许撤票／撤回或延时重开。

上述是本计划建议的首版口径，实施时需要在 UI 与工具说明中保持一致，不能只实现「有截止时间」，遗漏提前完成通知。

## 6 权限、修改与一致性

所有 API、卡片、Agent 工具和后台处理调用同一领域服务。身份来自认证用户映射的稳定 `member_id`，不相信客户端或模型提供的作者、家庭、投票人和报名人。

| 操作者 | 查看 | 本人参与 | 修改定义／结束 | 删除 |
| --- | --- | --- | --- | --- |
| 当前家庭有效创建者 | 销毁前允许 | 进行中允许 | 进行中按字段规则允许 | 销毁前允许 |
| 当前家庭其他有效成员 | 销毁前允许 | 进行中允许 | 禁止 | 禁止 |
| 已退出／停用成员、家庭外用户 | 禁止 | 禁止 | 禁止 | 禁止 |
| 无家庭业务身份的技术管理员 | 不因技术角色获得权限 | 禁止 | 禁止 | 禁止 |

关闭后禁止编辑定义及参与记录，创建者仍可删除；销毁时间也冻结，避免结果被事后长期保留。活动进行中修改任一截止都必须重新验证时间关系及当前时刻，不能把过去截止延后绕过已结束状态。

定义版本 `definition_version`、本人参与版本 `participation_version`、资源修订号 `revision` 分开：他人刚参与不能让自己的合法提交仅因总人数变化全部冲突。本人并发改票按本人版本防覆盖；定义改变后按当前规则重新校验，不接受旧规则下非法请求。限额检查、唯一性、计数及结束事件使用同一文件锁／事务。

每个写操作带 `request_id`，同 ID 同参数返回同一结果，同 ID 不同参数拒绝。销毁后的旧请求、草稿提交和插件 replay 不能重建活动。操作未知时核实实际持久化结果再显示成功；网络失败保留本人输入，重新联网先核实版本与状态，不自动后台投票或发布。

## 7 存储、API 与留言板整合

### 7.1 独立活动账本

新增 `FamilyActivityStore`，建议保存到家庭数据目录的 `family-activities.json`，复用 `TaskStore` 的文件锁、原子写入、备份模式；由 `FamilyPollService`、`FamilyRelayService` 承担各自规则，共享生命周期与权限实现。选票与接龙记录不写入 `tasks.json` 或便笺 `content_blocks`。

建议集合：

- `activities`：ID、kind、家庭、创建者、标题说明、时间、配置、完成成员快照、版本、状态和结束原因。
- `votes`／`entries`：以活动和成员唯一定位，保存本人数据、版本、更新时间；接龙另存稳定序号。
- `publications`：活动对应的留言板发布记录、资源引用、发布时间，不复制题目与统计。
- `drafts`：创建者、类型、配置、版本、会话／分支、草稿到期、已提交资源 ID。
- `notifications`／`outbox`：同事务生成的结束通知事件与投递状态。
- `operations`／`events`：幂等指纹、最小审计和防重放标识；不记录整份内容快照。

活动和活动发布记录处于同一个账本事务，避免「已创建但未上留言板」或孤立发布条目。便笺继续使用原 `BoardStore`，不做跨两个 JSON 文件的伪事务。

新增留言板 feed 聚合层，读取便笺与活动发布记录，返回类型联合 `BoardItem`：`item_id`、`kind`、`resource`、发布时间、时效及经过授权的摘要。按 `(published_at, item_id)` 稳定排序并使用统一不透明游标，不能先各取一页再在浏览器随意拼接导致漏项／重复。旧 `/board/posts` 保持便笺契约，新工作台切换到 `/board/feed`。活动摘要从权威记录派生，不保存第二套参与统计。

### 7.2 建议业务 API

投票使用 `/api/home/polls`，接龙使用 `/api/home/relays`，均提供：

| 方法／路径 | 用途 |
| --- | --- |
| `POST /`、`GET /` | 创建并发布、查询当前有权查看的活动 |
| `GET /{id}`、`GET /{id}/card` | 权威详情／交互视图 |
| `PATCH /{id}` | 按定义版本修改允许字段 |
| `POST /{id}/close` | 创建者主动结束 |
| `DELETE /{id}` | 创建者销毁，带请求 ID 与预期版本 |
| `POST /drafts`、`GET/PATCH /drafts/{id}`、`POST /drafts/{id}/commit` | 草稿补充与一次发布 |

投票增加 `PUT/DELETE /{id}/my-vote`；接龙增加 `PUT/DELETE /{id}/my-entry`。采用有明确字段的 Pydantic 输入与动作联合，不暴露任意 JSON Patch。删除本人参与记录不等于删除活动。

卡片沿用 `schema_version=1`、`kind=poll/relay`、`resource.type=family_poll/family_relay`；草稿对应 `family_poll_draft/family_relay_draft`。视图返回 `server_now`、`valid_until=expires_at`、`participation_deadline_at`、`next_transition_at`、状态、定义／本人版本和逐动作 `capabilities`。参与截止不占用存在期限字段；关闭后 `read_only=true` 仍可由能力声明允许创建者删除。

新接口统一 `private, no-store`，列表、详情、卡片与参与写入口均检查权限和时间。未授权和已销毁资源使用一致不可访问响应，避免泄露活动是否曾存在。客户端据服务端时间显示倒计时及刷新，服务端时钟是最终判断依据。

## 8 Agent 与交互卡片

### 8.1 原生工具

分别新增 `tool_plugins/family_polls/`、`tool_plugins/family_relays/`，每个插件声明一种卡片类型，适配当前单个插件 `cards.kind` 的清单格式，不为本功能修改整个插件协议。

工具建议命名：`family_poll_create/list/get/update/close/delete/vote/withdraw_vote`、`family_relay_create/list/get/update/close/delete/join/update_entry/withdraw_entry`，各自补充 `draft_get/draft_update`。UI 草稿提交和 Agent 草稿补充调用同一服务。

- 完整 Schema 通过 `tool_load` 按需加载，登记中文类别与「家庭投票、接龙、报名、改票、截止、销毁」等检索词；不加入首轮工具全集，不增加匹配数或保留数硬上限。
- 保留 Skill 权限、任务隔离、checkpoint 和 `replay_policy=revalidate`；重放先核实资源与操作账本，销毁后不得返回缓存正文或假成功。
- 明确「创建家庭投票／接龙」表示创建此家庭共享功能，直接创建并发布，不加额外确认；工具说明和回执明确家庭可见。仅说「帮我拟个投票」或信息不足时返回尚未发布的草稿。
- 这项默认发布行为是本次产品要求对 013 中“创建与发布分开”的具体化：首版家庭活动没有私人已发布状态；草稿仍私有。活动与发布记录模型分离，后续才能独立扩展撤下能力。
- 自然语言修改先解析真实资源 ID；同名多个活动时返回候选，禁止任意选中。普通成员说「修改投票」只获得本人参与能力，不能因此修改题目。
- Agent 代当前登录成员参与必须有明确指令，不能因创建了活动就自动替全家投票／报名；参与身份不允许模型指定他人。

示例：「发起家庭投票，周末吃火锅还是烧烤，今晚八点截止，明晚八点自动删除，结束提醒我」可直接发布；「帮我创建家庭投票」缺题目和选项时返回草稿。未指定截止时使用清楚展示的「不设截止／长期保留」，若说「今晚截止」但缺少可确定时刻，则要求在草稿补充，不静默猜时间。

### 8.2 展示、回执与会话保护

工具成功后由服务端生成真实资源引用，经 `CardPresenter` 白名单校验后进入流式事件、最终消息和持久化 `ui_blocks`。卡片与留言板共用权威对象；同一位置沿用 `card_id` 去重，多个位置按 `resource` 同步。

新增活动回执与最新上下文校验：以本轮原生工具结果及持久化操作证明创建、修改、删除，草稿不能说「已发布」，失败不能说「已保存」。不能只改提示词。复用便笺对个人会话、分支草稿与共享会话的保护模式，避免参与明细流入不可撤权的共享聊天。

聊天默认只保存引用和最小回执，不把完整选项、名单、选票和接龙条目复制进最终正文。实现时检查原始工具结果、Run 产物和 checkpoint 是否持久化正文：可重建展示数据使用最小引用，确需持久化的活动派生数据必须登记销毁关联并同步清理。历史恢复和上下文构建重新鉴权，不直接重放旧正文。

原始用户输入及用户主动发送的聊天内容仍由聊天生命周期管理；活动销毁不能承诺擦除用户自己发送的聊天或已经送达系统通知中心的内容。活动产生的卡片、缓存、结果副本与备份则必须随活动销毁，文案明确边界。

通过 `resource_changed` 失效活动详情、聊天卡片和 feed；本地事件即时同步当前页面，跨成员以现有定时刷新、窗口聚焦核实为首版方案。活动临界时间有定时刷新；其他成员变化的可见延迟以轮询间隔为界，不把浏览器事件误称为跨设备实时推送。

## 9 创建者通知、后台处理与销毁

### 9.1 通知可靠性

活动结束和结束通知事件在同一账本事务内提交，事件唯一键采用 `activity_id:closed`。提前完成后到原截止时间不再发第二次。推送失败不能回滚投票、接龙或结束结果。

站内通知是默认可用渠道，现有通知列表、已读及全部已读接口通过来源适配纳入活动通知，保留账号隔离；通知只面向创建者，不能调用未做受众过滤的旧入口。Web Push 在服务配置、设备订阅、账号有效且用户授权时发送，未授权时仍有站内提醒。

现有 `ChatNotifications` 的 outbox 与聊天 `jobs` 关联，不能直接伪造聊天 job 来发送活动通知。抽取其可复用设备校验／推送发送部分或增加业务发送适配，活动拥有独立 outbox。投递过程有认领、超时恢复、有限重试、退避与设备失效处理，不在持有活动文件锁时发网络请求。账号注销、活动销毁或创建者失去家庭资格后取消待发送事件。

推送只发送通用「家庭投票／接龙已结束，点击查看」，不含题目和参与明细；站内结果在点击时鉴权读取。使用稳定事件 tag 降低重复，业务事件只产生一次；外部推送崩溃重试可能重复送达，不承诺网络端到端严格一次。

### 9.2 后台时效工作

新增独立生命周期循环，启动立即处理首轮，其后建议每 10 秒扫描参与截止、成员变更、销毁和投递队列，不受提醒总开关或是否打开工作台影响。多 worker 使用既有存储锁与事件认领保证幂等，单条故障不阻塞其他活动，并提供脱敏失败日志。

服务停止期间无法执行清理或发送；重启后先核实存在期限，已销毁对象不补发结果明细，尚存在的已结束活动补齐一次结束事件。读写入口同样核实时间，不因轮询延迟留下可参与窗口。UI 到点按服务端时间关闭交互／清除正文，再向服务端核实。

### 9.3 自动与手动销毁

共用可恢复、可重复执行的销毁流程：

1. 存在期限到达即禁止详情、列表摘要、卡片、工具与参与访问。
2. 删除活动定义、选票、接龙条目、发布记录、草稿及其提交副本；清除活动派生的正文审计与缓存。
3. 清理活动账本备份和已登记的派生工具产物；备份恢复时先重放销毁标识／执行到期净化，避免旧备份复活手动删除的数据。
4. 取消 outbox，移除站内通知中的内容与跳转，仅可留无业务正文的通用销毁提示；已送到外部系统的通用推送不可远程撤回。
5. 保留最小资源 ID、请求指纹与销毁标识用于拒绝重放，不留标题、选项、成员条目和原始请求内容。日志中也不写这些正文。
6. 使 feed、详情、聊天历史卡片和账号缓存失效；销毁后的引用只显示「该家庭活动已不可访问」。

首版活动不带图片附件，因此不增加一套活动媒体生命周期；以后支持图片必须接入相同的授权和最后引用清理规则。
