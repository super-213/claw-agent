# Home Agent 现代 Web 技术升级计划

> 项目仓库：<https://github.com/super-213/claw-agent>  
> 计划版本：v1.0  
> 制定日期：2026-10-27  
> 状态：P0/P1/P2 代码实施与 Chrome 自动化验收完成；历史数据事故处置与真实设备验收尚未关闭
> 实施记录：[当前架构与安全基线](claw-agent-web-baseline.md) · [配置、恢复与验收](claw-agent-web-upgrade.md)

## 1. 背景与目标

Home Agent 面向本地部署的家庭 AI Agent 场景。根据此前对公开仓库说明、依赖和部分配置的初步评估，项目已有 React、TypeScript、Vite、FastAPI、PWA、流式响应，以及 Agent 工具调用、审批与任务恢复的基础。**本计划并不等于完整源码审计**；每个涉及既有功能的结论均须在实施前复核。

目标：

1. 优先保证家庭资料、账户与密钥的安全性。
2. 在不大规模重构现有架构的前提下，扩展可维护的 Agent 工具生态。
3. 增强 PWA 的离线可用性和跨设备体验。
4. 逐步改善身份验证与 UI 体验。
5. 仅在明确的需求或性能证据出现后引入 WASM、WebGPU、CRDT 等技术。

### 原则

- **保留主架构**：优先沿用 React + TypeScript + Vite + FastAPI + PWA。
- **先验证后变更**：通过代码审计确认功能是否已经存在，避免重复建设。
- **权限优先**：外部工具必须经过统一的授权、参数校验、审批、审计与隔离。
- **渐进增强**：新功能应可选、可回退、不破坏已有任务。
- **数据最小化**：不默认缓存敏感家庭资料；禁止跨账号混用缓存。

## 3. 分阶段计划

### 阶段 0：安全与技术基线核查（P0，必须先完成）

**目的**：在扩展能力前消除潜在敏感信息泄露与权限风险，并建立可回归的基线。

**任务**

- [x] 检查 Git 已跟踪文件和历史提交，确认 `.webui_secret_key`、`.data`、`node_modules` 是否确实被提交；不要仅凭目录列表判定泄露。
- [ ] 若发现有效密钥暴露：先轮换/吊销密钥，再按实际影响清理 Git 历史并通知相关协作者。
- [ ] 若发现真实用户数据或家庭资料被跟踪：阻止继续提交，评估历史暴露范围并制定清理方案。
- [x] 补充 `.gitignore`、示例环境变量文件、密钥生成/轮换文档；确保忽略规则与 Git 跟踪状态一致。
- [x] 梳理身份与权限模型：用户、家庭成员、共享数据、工具执行者、批准者。
- [x] 检查 PWA 缓存策略、退出登录时缓存清理、Push 订阅绑定、跨账号数据隔离。
- [x] 为 Tool Registry、工具审批、任务恢复、流式响应增加关键路径测试。
- [x] 输出《当前架构与安全基线》：已实现功能、已知缺口、测试结果和风险清单。

**验收标准**

- [ ] 不再存在已知的有效凭证或私人资料被公开跟踪的情况；相关凭证已轮换。
- [x] 不同家庭成员无法通过浏览器缓存或 API 访问越权数据。
- [x] 关键工具调用、审批与任务恢复测试通过，形成可重复执行的回归基线。

**交付物**：安全检查报告、必要配置修复、回归测试集、架构基线文档。

### 阶段 1：MCP 工具接入（P1）

**目的**：让 Agent 复用外部工具生态，不重写核心 Orchestrator。

**建议架构**

```text
Agent Orchestrator
       │
Unified Tool Registry
       ├── Native Skills / Tools
       └── MCP Client Adapter
                └── 受信任 MCP Server（先只读）
```

**任务**

- [x] 确认现有 Tool Registry 的工具定义、权限校验、工具执行和审计扩展点。
- [x] 设计 MCP Adapter：工具发现、schema 映射、参数校验、结果封装、错误处理。
- [x] 建立 MCP Server allowlist、连接配置、凭证保管、资源限制与超时控制。
- [x] 将 MCP 工具接入已有身份授权、敏感操作审批与审计流程；不得直接绕过审批。
- [x] 接入一个**只读** MCP Server，优先验证家庭服务状态查询。
- [x] 加入工具不可用、请求超时、恶意提示注入、无权限用户调用等测试。
- [x] 增加可观测性：调用耗时、成功率、失败原因、审批记录。

**验收标准**

- [x] Agent 能发现并调用指定只读 MCP 工具，响应结果符合既有工具格式。
- [x] 未授权工具无法被调用；工具层异常不会破坏 Agent 任务状态。
- [x] 原有 Native Tools 不受影响，能够通过配置停用 MCP Adapter。

**交付物**：MCP Adapter、示例 Server 配置、权限测试和集成文档。

---

### 阶段 2：PWA 离线增强（P1）

**目的**：从“可安装的网页”升级为“断网仍可查看部分必要信息的家庭应用”。

**第一期：只读离线体验**

- [x] 明确缓存白名单：近期会话摘要、家庭事项与资料元数据；敏感正文默认不缓存。
- [x] 设计 IndexedDB schema、数据版本、TTL、容量配额与升级迁移方式。
- [x] 按用户/家庭作用域隔离离线数据；实现退出登录与撤销权限后的缓存清理策略。
- [x] UI 明确显示离线状态、最后同步时间和数据可能过期的提示。
- [x] 联网后执行重新鉴权和增量校验；权限已撤销的数据必须失效。

**第二期：有限离线写入**

- [x] 仅选取低风险操作试点，例如新增个人备忘；不允许离线执行高风险 Agent 工具。
- [x] 建立本地待同步队列，使用请求唯一 ID 保证幂等。
- [x] 复用服务端版本条件（如 `expected_version`）处理冲突，不静默覆盖他人修改。
- [x] 设计同步失败、冲突提示、取消重试和人工解决入口。

**验收标准**

- [x] 已授权成员可在断网后查看规定范围内的已缓存内容。
- [x] 切换账户与退出登录不会显示前一账户缓存；权限回收后重新在线访问不能读取旧授权数据。
- [x] 试点离线备忘只提交一次；发生版本冲突时明确提示而不丢失本地更改。

**交付物**：IndexedDB 数据层、同步模块、离线状态 UI、安全回归测试。

**暂不引入 CRDT**：家庭事项优先采用服务端权威数据 + 乐观并发控制。多人实时编辑文档形成明确需求后，再评估 Yjs / Automerge。

### 阶段 3：登录和 UI 体验升级（P2）

#### A. Passkeys / WebAuthn

- [x] 审查现有会话、注册、登录、成员绑定和账号恢复流程。
- [x] 设计 Passkeys 的注册、验证、设备丢失与恢复机制。
- [x] 服务端验证 WebAuthn challenge、origin、RP ID、签名与重放保护。
- [x] 分阶段开放 Passkeys，保留安全的后备认证方案。

**验收**：支持符合条件的设备通过通行密钥登录；丢失单个设备不会导致账号永久不可恢复。

#### B. 新一代 CSS 与页面交互

- [x] 用 Container Queries 改造对话卡片、事项列表和家庭看板组件。
- [x] 选择性添加 View Transitions，保持减少动态效果（`prefers-reduced-motion`）支持。
- [x] 评估 Popover API / Anchor Positioning 用于菜单、成员选择与工具详情浮层。
- [x] 对未支持的浏览器提供渐进降级与可访问性测试。

**验收**：手机、平板、桌面布局可用；新动画不破坏键盘导航、无障碍或低性能设备体验。

**交付物**：Passkeys 认证模块、认证恢复文档、响应式组件升级与兼容性测试。

### 阶段 4：基于证据的高级技术试点（P3，条件触发）

| 候选技术 | 触发条件 | 最小验证方案 | 暂不采用的原因 |
| --- | --- | --- | --- |
| WASM 文档预处理 | 图片/文档上传成为显著瓶颈 | 比较浏览器原生 API、WASM、服务端处理的耗时/质量 | 引入构建体积与兼容性成本 |
| WebGPU 端侧 AI | 有明确离线 Embedding / 推理场景 | 对目标设备测试首包大小、内存、耗电和推理速度 | 服务端模型能力已存在，可能重复计算 |
| CRDT | 多人同一文档实时协作成为核心需求 | 用 Yjs / Automerge 实现隔离原型 | 家庭事项无需复杂最终一致性模型 |
| WebTransport | WebSocket / NDJSON 不满足低延迟多路传输需求 | 对比延迟、重连、代理兼容性 | 当前流式响应足以支持多数 Agent 任务 |
| Edge Computing | 跨地域访问延迟成为主要限制 | 测试边缘网关与源站通信 | 本地服务器是数据与执行中心 |
| A2A | 确有跨独立 Agent 协作需求 | 用两个受限 Agent 验证交接和权限 | 单一 Orchestrator + 工具系统更简单 |
| React Server Components | 页面首屏/SEO 有持续性问题 | 先用真实指标比较 SSR 与现有 SPA | 当前 React SPA + FastAPI 迁移成本高 |
| DID / Web5 | 需要跨平台、自主身份互操作 | 先评估可验证凭证的真实使用场景 | 普通家庭认证用 Passkeys 更直接 |

**试点评估统一指标**：用户价值、运行复杂度、安全影响、CPU/GPU/内存占用、加载体积、跨浏览器兼容性、维护成本与回退能力。

## 3.1 实施状态与待关闭项（2026-10-27）

源码与自动化测试已落实 MCP 只读接入、离线查看/个人备忘、Passkeys 及 CSS/交互增强。上方勾选代表代码与相应自动化检查已实现，不代表事故处置、生产启用或真实设备验收完成。

P0 核查发现历史中有会话、密码哈希及旧密钥。旧密钥已轮换，依赖停止跟踪，提交前检查已启用；**2 个本地账号仍需停服重置密码，仓库维护者仍需完成共享历史清理及通知**。当前未改写远端历史或发送对外消息。P1/P2 默认可回退，MCP 和 Passkeys 仍需按部署环境显式配置启用。

浏览器兼容范围以实施文档的实际测试结果为准；真实家庭设备上的 iOS/Safari/Android 与设备丢失恢复需由部署方完成验收。

## 5. 跨阶段非功能性要求

- **安全**：最小权限、敏感工具审批、密钥隔离、用户/家庭租户隔离、缓存撤销、可审计性。
- **可靠性**：任务断线后可恢复、幂等处理、错误可见、超时受控、升级可回退。
- **性能**：新增功能需有前后对比数据；避免前端加载体积和家庭服务器常驻资源无意义增加。
- **兼容性**：针对实际家庭成员使用的浏览器/设备测试；优先渐进增强。
- **维护性**：模块接口清晰、配置可关闭、文档与自动化测试同步更新。

## 6. 推荐执行顺序与近期里程碑

1. **M0：代码与安全基线确认** — 证明仓库状态、真实风险和已有能力。
2. **M1：MCP 只读工具端到端跑通** — 用户授权、发现、调用、审计和失败恢复全部可验证。
3. **M2：离线可查看家庭数据** — 实现缓存权限边界、离线状态、重新同步。
4. **M3：离线备忘与 Passkeys** — 分别完成低风险写入与更便捷的成员登录。
5. **M4：UI 体验增强与高级技术试点评审** — 只推进已有测量证据支持的方案。

**近期最小验证（MVP）**：在保持现有 React + FastAPI 主架构不变的前提下，完成安全基线、接入一个只读 MCP Server、实现一个可离线查看且不会跨账户泄露的页面。这三项构成第一轮可演示的升级成果。

## 7. 明确不做的事

- 不为了追新而将现有 SPA 全面迁移至 Next.js / RSC。
- 不将 Agent 的长期后台执行转移到 Service Worker。
- 不在没有性能基准数据时使用 WebGPU 或 WASM 重写现有后端。
- 不把 CRDT 当成普通家庭事项同步的默认方案。
- 不允许 MCP 工具绕过已有权限、审批和审计。
- 不将“采用 Web5”当作产品目标；以明确的用户价值和可验收的功能为目标。
